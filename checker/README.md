# 厳選チェッカー（きのみタイプ・食材タイプ・スキルタイプ）

ポケモンスリープのきのみタイプ（最終進化形31匹）・食材タイプ（最終進化形40匹）・スキルタイプ（最終進化形54匹）向けの厳選チェッカーです。画面上部のタブでタイプを切り替えます。

- 食材タイプ: 狙い食材・食材配列・サブスキル・性格から、狙い食材の1日あたりの期待個数を計算します。おてつだいボーナスを持つ個体は、ほかの4匹（同じポケモン）が増やす狙い食材も足して比べます。
- きのみタイプ: サブスキル・性格から、1日あたりのきのみエナジーの期待値に、おてつだいボーナスでチームのほかの4匹が増やすエナジーを足した値を計算します。
- スキルタイプ: サブスキル・性格から、1日あたりのメインスキルの期待発動回数を計算します。おてつだいボーナスを持つ個体は、ほかの4匹（同じポケモン）が増やす発動回数も足して比べます。

どれも無補正個体との比較と、同等以上の個体になる確率・平均何匹に1匹を表示します。サブスキル・性格のデータ（`../js/constants.js`）、げんきとおてつだいのタイミング計算・おてつだい時間と確率の丸め・スキル抽選とストック・サブスキル抽選モデル（`../js/calc.js`）、土台のスタイル（`../css/style.css`）はリポジトリ直下の共通部分にあり、その計算モデルはリポジトリ直下の README.md にまとめています。

## 使い方

- 画面上部のタブ（色の点・タイプ名・匹数）でタイプを選び、その下のポケモンのカードをタップしてポケモンを選びます。タブの横の虫めがねからは、3タイプすべてから名前で探せます。`?mon=flygon` のように URL でも指定でき、タブもそのポケモンのタイプになります。
- タブを切り替えると、そのタイプで前回選んだポケモンに戻ります。選んだポケモンと、食材タイプの狙い食材は次に開いたときにも使います。
- ポケモンやタイプを切り替えても、サブスキルと性格はそのまま残ります。食材配列は選び直しになります。
- 幅の広い画面では、入力を左、結果を右の2列に並べます。
- アプリバーの右に、表示テーマ（自動 → ライト → ダークの順に切り替え。選んだものは次に開いたときも使う）と記録のボタン（このポケモンの記録の件数つき）があります。バージョン（v1.0）は画面の一番下（著作権表示の下）とログイン画面に小さく出します。
- 判定のすぐ上の「条件」の欄では、レベル（50 / 60 / 70 / 80）、日中の受け取り（きのみタイプは なし＝いつのまに育成 / 3時間ごと、食材タイプ・スキルタイプは 常にタップ / 3時間ごとで共通）といいキャンプチケット（なし / あり）をその場で切り替えられます。ほかの設定は「詳細」のダイアログで変え、今の値は「詳細」の横に要約して出します。選んだ値は次に開いたときも使います。
  - 詳細（3タイプ共通の設定）: ヒーラー（なし / 1匹 / 常に81%以上）、おてボのチーム効果（含めない / 含める）、げんきオールSの1回の回復量（整数）と1日の発動回数（小数第2位まで）。
  - 詳細（きのみタイプだけ）: フィールドボーナス（0〜85%の整数を手入力。−／＋は5の倍数に揃えて5%ずつ。33 なら＋で35、−で30）と、選んだポケモンのきのみを好きなきのみ（エナジー2倍）として扱うか（OFF / ON）。エナジーの値だけが変わり、無補正比・確率・記録は変わりません。ポケモンを切り替えても設定は残ります。
- 期待値はそのレベルで、そのレベルで開いている枠（Lv.50・60 は3枠、Lv.70 は4枠、Lv.80 は5枠）に入っているサブスキルで計算します。未入力の枠は「なし」、未選択の性格は無補正として計算します。食材の枠は Lv.60 で3つ目が開くので、Lv.50 では食材配列の Lv.60 の枠を使いません（食材タイプでは「未解放」と薄く出します）。狙い食材が Lv.60 の枠にしか出ない食材のとき、Lv.50 ではその食材を誰も拾えず、無補正の個体も0個になるので、無補正比・確率・順位は「—」にし、判定のカードに「ポテトは Lv.60 から出る食材です」と、そのレベルに切り替えるボタンを出します（記録もできません）。Lv.50 では、そうした食材の狙い食材のボタンは押せず、「Lv.60〜」と添えます。Lv.60 以上で選んでからレベルを下げたときは、狙い食材の選択はそのまま残り、Lv.60 以上に戻すと表示されます。
- 同等以上の確率・平均何匹に1匹・性能値の順位は、そのレベルで開いている枠のサブスキル・性格（食材タイプは開いている枠の食材配列）がすべてそろうと出ます。そろうまでは判定のカードに足りない入力（「サブスキル 2/3」「性格 —」など）を出します。
- 判定のカード（夜空色）には、同等以上の確率を大きく、無補正比、平均何匹に1匹を出します。ゲージは同等以上の確率を 0.1%〜100% の対数の目盛り（1% / 5% / 10% / 25% / 50%）に置き、左ほどめずらしい個体です。分布を計算している間は「計算中」と出します。カードの「記録する」で記録します。
- 下の帯は、判定のカードが画面の外にあるときだけ出し、同等以上の確率・無補正比・何匹に1匹と「記録」ボタンを1行で並べます。
- 「サブスキル・性格を消す」で消した入力と、削除した記録は、5秒間出るお知らせの「元に戻す」で戻せます。
- 結果の下の「くわしい数値」は、見出し（おてつだい・きのみ・無補正個体との比較など）ごとに開閉します。
- 結果の下の「レベル別」は、Lv.50 / 60 / 70 / 80 の無補正比と同等以上の確率を並べる一覧です。閉じているときは、同等以上の確率が一番低い（一番良い）レベルを「最高 Lv.80・4.80%」のように1行で出し、タップで開くと4つのレベルを並べます（表示中のレベルに「表示中」、一番良いレベルに「最高」）。行をタップするとそのレベルに切り替わります。そのレベルの枠の入力が足りないときは「未入力」、狙い食材がまだ出ないときは「Lv.60〜」と出します。ほかのレベルの分布は、今のレベルの分布のあとに読み込み・計算します。開いているかどうかは保存し、次に開いたときも同じにします。
- サブスキルは、選んだレベルに関係なく常に5枠（Lv.10 / 25 / 50 / 70 / 80）を入力できます。枠をタップして、ダイアログで選びます。見出しの横に入力した枠の数（3 / 5枠など）を出します。今のレベルでまだ開いていない枠には「未解放」と添え、点線の枠にします（入れておくと、そのレベルを選んだときに使います）。レベルの低い枠から順に入れ、手前の枠が空いている枠は選べません。1つ選ぶと次の空き枠に進み、5枠すべてが埋まるとダイアログは自動で閉じます（直すときはもう一度開きます）。途中でも「閉じる」で閉じられます。ダイアログの上の枠ボタンで入れ直す枠を切り替えられます。どこかの枠で選んでいるもの（枠のレベルが付いたもの）を押すとその枠から外れ、その枠の入力に移ります。途中の枠を外したときは、そこを埋めるまで後ろの枠は選べません。「全枠クリア」ですべての枠を空にします。
- ダイアログにはゲーム内の全17種を、金色サブスキルと系統×サイズ（M / S / L）の表で並べます。ほかの枠で選んでいるものにはその枠のレベルを付けます。そのタイプの計算に効かないもの（睡眠EXPボーナスなど）は「なし他」として計算します。
- 性格は、行が▲上昇・列が▼下降の5×5の表から名前で選びます。そのタイプの計算に効く補正がない性格（無補正と同じ結果になるもの）は薄い色で表示します。
- 「同等以上の確率」は、同じポケモン・同じパラメーター・同じ抽選条件（フレンドメダルによる金枠確定なし）で、その個体の無補正比以上になる推定確率です。「平均何匹に1匹」はその逆数で、丸める前の確率から計算します。
- 「性能値の順位」は参考値で、無補正比が異なる組み合わせ（分布の行）の中で自分より高い値の数 + 1 です。組み合わせごとの出やすさを考えないので、順位 ÷ 行数は確率になりません（たとえば 143位 / 2,009通り でも、同等以上の確率は 0.74%）。記録の一覧には確率と何匹に1匹だけを出します。
- 無補正比の差が相対で 1e-7 以内のものは同じ性能とみなし、分布の1行にまとめます（計算の丸め誤差で分かれないようにするため）。順位・同等以上の確率も同じ基準で比べます。整合性は `node tests/check-dist.mjs` で確かめられます（確率の合計が1、確率が順位とともに増える、同じ性能を同じに扱う）。
- 計算した上位%の分布はブラウザ（IndexedDB）に保存し、次からは計算せずに読み込みます。保存は最大300件で、最後に使ったのが古いものから消します（使った時刻の記録は1日に1回まで更新します）。計算方法（`MODEL_VERSION`）・公開した版・ポケモンの基礎値・共通データ・条件のどれかが変わったときは、保存済みの分布を使わずに計算し直します。
- 既定の条件（Lv.50〜80・チケットあり／なし・ヒーラー1匹・回復量18・発動回数5・チーム効果を含める・日中の受け取りはきのみタイプ「なし」、食材・スキルタイプ「常にタップ」）の分布は、公開時に事前計算して `dist/` に置いてあります。保存済みの分布がなければ、そのポケモン・条件のファイル（gzip で数KB〜200KB）だけを取得して表示し、IndexedDB にも保存します。ほかの条件や、ファイルを取れない・中身が合わない（版や条件が違う・壊れている）・6秒たっても届かないときは、今までどおり計算します。値は計算したものとビットまで同じです。
- 記録には、入力してあるサブスキル（低い枠から続けて入っている分）をすべて保存します。一覧はポケモンごとに、今のレベルで開いている枠のサブスキル（食材タイプは食材配列も）がそろっている記録を出し、その枠で評価します。5枠の記録は Lv.50〜80 のどれでも、3枠の記録は Lv.50・60 で出ます。以前の「Lv.50まで」の記録（3枠）は Lv.50・60 で出ます。統合前の食材タイプ版・きのみタイプ版の記録もそのまま表示されます。
- 記録はアプリバーの記録ボタンから開くダイアログに並べます。記録の行をタップすると、ダイアログを閉じてその個体の食材配列・サブスキル・性格を入力に戻し、結果と判定がその個体の値になります。今の入力と同じ記録には「表示中」を付けます。記録を順にタップして見比べられます。性格の名前がない古い記録は、上昇・下降の補正だけを戻します。
- 以前の URL（リポジトリ直下のミュウツー版・`../ingredient/`・`../berry/`）は、ポケモンの指定を引き継いでこのページに移動します。

## 構成

- `index.html` — マークアップ
- `css/theme.css` — 見た目「夜のノート」（生成りの地に夜空色の文字、タイプの色はアクセント。文字は Zen Kaku Gothic New、数字は Outfit。土台のレイアウトは `../css/style.css`）
- `js/types.js` — 3タイプの定義をまとめる
- `js/state.js` — アプリ状態管理・localStorage永続化（記録は統合前と同じ `iglog`・`bflog` とスキルタイプの `sklog`、共通の設定は `ck` 接頭辞）
- `js/ui.js` — DOM描画・イベント処理
- `js/picker.js` — サブスキル・性格を選ぶダイアログの並びと表示名
- `js/worker.js` — 上位%の分布を「IndexedDB → 事前計算のファイル → 計算」の順に探すWeb Worker。ポケモンや条件を変えたら、前の条件の計算をやめて今の条件から計算する
- `js/distcache.js` — 計算した分布を IndexedDB に保存・読み込みする。保存のキー（`cacheKey`）と、公開の版を除いたキー（`dataKey`）
- `js/precomputed.js` — 事前計算する条件の一覧、ファイルの場所・中身の形（書き出しと読み込み）、ファイルの取得。Node（`../scripts/precompute-dist.mjs`）と画面で同じものを使う
- `dist/` — 事前計算した分布（公開時に作る。リポジトリには入れない）。`v<MODEL_VERSION>/<タイプ>/<ポケモン>/lv<レベル>-<camp|nocamp>[-<狙い食材>].json.gz`。作り方は [README](../README.md#事前計算した分布)
- `js/main.js` — エントリーポイント
- `js/engine.js` — 3タイプの計算エンジンが共有する部品（性格・サブスキルの倍率、げんきとおてつだいの区間、基礎値からの時間・確率・所持数、食材配列のパターン、上位%の分布の数え上げ、同等以上の確率と順位）
- `js/ingredient/` — 食材タイプの定義（`constants.js`）・期待値計算エンジン（`calc.js`、DOM非依存）・ポケモンの基礎値（`mons.js`）
- `js/berry/` — きのみタイプの定義・期待値計算エンジン・ポケモンの基礎値
- `js/skill/` — スキルタイプの定義・期待値計算エンジン・ポケモンの基礎値

## 食材タイプ

### ポケモンのデータ

`js/ingredient/mons.js` の `MONS` にポケモンごとの基礎値（おてつだい時間・食材確率・最大所持数・食材スロットの候補と個数）を持ちます。データは [RaenonX ポケスリ攻略ツール](https://pks.raenonx.cc/ja/pokedex) から 2026年9月25日に取得しました。

- 対象は、とくいが「食材」で、これ以上進化しないポケモンです。パンプジンは大きさでおてつだい時間と最大所持数が違うので、4つを別々に持ちます。

### 計算モデル

「狙い食材の1日の期待個数 ＋ おてつだいボーナスによるチームへの効果」を、無補正個体（サブスキルなし・無補正性格）のうち狙い食材が最も多く取れる食材配列（フライゴンのアボカドなら AAA）の値で割った比を順位の基準にしています。

- おてつだい時間・いいキャンプチケットは共通の計算モデル（リポジトリ直下の README.md）のとおり。げんき（ヒーラー・料理の回復・性格のげんき回復量補正）とおてつだい回数（期待値なので小数）はきのみタイプと同じ規則で、ヒーラーの設定もきのみタイプと共通。
- 食材確率 = 基礎値 × 性格(↑1.2 / ↓0.8) × (1 + 食材確率アップ合計) を小数第4位まで切り捨てた値（にとよんツールと同じ）。
- 食材おてつだいでは、食材配列の開いているスロット（Lv.1 / Lv.30 / Lv.60。Lv.50 は Lv.1 / Lv.30 の2つ）から均等に1つ選び、そのスロットの食材を拾う（おてつだいのたびに解放済みの枠から選ぶ確率。捕獲時に配列が決まる確率とは別）。
- 日中の受け取り: 「常にタップ」は所持数があふれない。「3時間ごと」は起床から3・6・9・12・15時間後と就寝時に受け取り、区間ごとに所持数0から追う。
- 睡眠中（と「3時間ごと」の日中の区間）は所持数0から始まり、きのみ（1個、きのみの数Sで2個）と食材（狙い以外も含む）で埋まっていく。所持数を超えた分は捨てられ、満タン後のおてつだいでは食材は増えない。回数が小数の区間は前後の整数回の結果を混ぜる。
- チームへの効果: 自分がおてつだいボーナスを持つとき、ほかの4匹（同じポケモン・狙い食材が最も多い食材配列・サブスキルなし・無補正性格・同じパラメーター）のおてつだいスピードが5%上がったぶんの狙い食材の増加を足す。おてボ1つで無補正の約1.21倍になる（食材確率アップMは約1.32倍。ヒーラー1匹・常にタップ・チケットあり）。オフにすると自分の狙い食材の個数だけで比べる。
- 性格のスキル補正は食材に影響しないので「なし他」として扱う。
- この計算は [にとよんツール（ポケスリ 個体値計算機）](https://nitoyon.github.io/pokesleep-tool/iv/) の食材の個数と、40匹 × Lv.60 / Lv.80 × サブスキル6通り × 性格7通り × パラメーター5通り × すべての食材配列（狙い食材ごと）の199,500通りを比べ、差が浮動小数の誤差（相対2e-15以下）であることを確かめた（ver1.5）。
- 上位%の分布は、サブスキル（色別抽選・重複なし）と性格25種を共通のモデルで、食材配列は捕獲時の出現率で数え上げる。出現率は [RaenonX の調査](https://hackmd.io/@raenonx-pokemon-sleep/rJj6yeIlWe)（1,153件）による。Lv.30 のスロット（候補 A・B）は A が 1/3・B が 2/3、Lv.60 のスロットは候補が3つなら等確率、2つなら A が 1/3・B が 2/3 で、スロットどうしは独立（AAA・AAB・AAC 各11.1%、ABA・ABB・ABC 各22.2%）。全タイプのデータで、候補が A・B・C の順に並んでいることを確かめた。

#### 考慮していないもの

- 食材ごとのエネルギー（狙い食材の個数のみで比較。エナジーで比べると、1個のエナジーが高い食材の混ざる配列が AAA より上に来るため）。
- メインスキル（食材ゲットSなど）の効果。
- ほかのメンバーを別のポケモン（きのみタイプなど）にすること。

### 計算モデル

「自分のきのみの1日の期待エナジー ＋ おてつだいボーナスによるチームへの効果」を、無補正個体（サブスキルなし・無補正性格）の自分のきのみエナジーで割った比を順位の基準にしています。

- おてつだい時間・いいキャンプチケットは共通の計算モデル（リポジトリ直下の README.md）のとおり。げんきとおてつだい回数は次のとおり（きのみタイプだけ）。
- おてつだい回数: 期待値なので小数で数える。次のおてつだいにかかる時間は、そのおてつだいを始めた時点のげんきで決まる。起床中は受け取りの区間ごとに、完了した回数と、最後の区間の終わりまでに進んだ途中の分を数える（区間をまたいだおてつだいは次の区間に入る）。睡眠中は就寝時から数え直す。回数が小数の区間の所持数は、前後の整数回の結果を小数部分の割合で混ぜる。日をまたぐ持ち越しは考えない。
- げんき: 起床時は睡眠による回復で100（げんき回復ボーナス持ちは105）。起床中・睡眠中を問わず10分ごとに1減り、0で止まる。ヒーラー（げんきオールS、チーム全員を回復）がいるときは、起床中（15.5時間）を1日の発動回数 + 1 等分した時刻に、1回ずつ回復量（既定18）だけ回復する（上限150。時刻は10分単位に切り捨て）。料理（起床から2・6・12時間後＝8時起床で10時・14時・20時）でも、そのときのげんきが80超で1、70超で2、…10超で8、10以下で9回復する。睡眠中は回復せず、就寝時の値から減っていく。既定（18×5回）では就寝時100・起床直前50（ver1.8 までの既定の18×3回では64・14）。げんき1以下はげんき0と同じ倍率（1.0）で数える。1日の発動回数が小数（2.5回など）のときは、前後の整数回の日（2回と3回）が小数部分の割合で混ざるものとして、それぞれの値を平均する。「常に81%以上」はげんきによる倍率を常に0.45とする。
- 日中の受け取り: 「なし」は一度も受け取らないので、所持数はずっと満タンで、すべてのおてつだいがきのみ（きのみの数Sの効果込み）になる（いつのまに育成）。食材確率と最大所持数は効かない。「3時間ごと」は起床から3・6・9・12・15時間後と就寝時に受け取って所持数を0に戻し、区間ごとに所持数0から追う（睡眠中は所持数0から次の起床まで）。どの区間も下の規則で所持数を埋める。
- この計算は [にとよんツール（ポケスリ 個体値計算機）](https://nitoyon.github.io/pokesleep-tool/iv/) のエナジーの「きのみ」と、同じ条件（Lv.60・食材配列 AAA）で31匹 × サブスキル5通り（げんき回復ボーナスを含む）× 性格8通り（げんき回復量の補正があるものを含む）× パラメーター6通りの7440通りを比べ、差が中央値0.02%・最大0.74%であることを確かめた。ver1.5 でおてつだい時間と食材確率の丸めを合わせ、31匹 × Lv.60 / Lv.80 × サブスキル6通り × 性格7通り × パラメーター5通り（食材配列は出現率で平均）の13,020通りで差が浮動小数の誤差（相対1e-15以下）になった。
- チームへの効果: 自分がおてつだいボーナスを持つとき、ほかのメンバー4匹（同じポケモン・サブスキルなし・無補正性格・同じパラメーター）のおてつだいスピードが5%上がったぶんのきのみエナジーの増加を足す。オフにすると自分のきのみエナジーだけで比べる。
- きのみ1個のエナジー = max(基礎 + Lv − 1, round(基礎 × 1.025^(Lv − 1)))。選んだレベル（Lv.50 / 60 / 70 / 80）で計算する。
- フィールドボーナスと好きなきのみ: きのみ1個のエナジー = ceil(ceil(上の値 × (1 + ボーナス% ÷ 100)) × (好きなら2))（にとよんツールの `getBerryStrength` と同じ1個ごとの切り上げ。ボーナスは整数で割り、浮動小数の誤差では切り上げない）。個数・所持数・食材確率には効かない。自分・ほかの4匹・無補正の個体はどれも同じポケモン・同じレベルなので同じ値になり、無補正比・分布・順位は補正なしと同じ。そのため計算エンジンと条件（`env`・分布の保存のキー）には入れず、表示の段で掛ける。整合性は `node tests/check-boost.mjs` で確かめる。
- きのみおてつだい1回で拾うきのみは、きのみタイプの2個（きのみの数Sで3個）。
- 満タンになるまでは、食材確率 = 基礎値 × 性格(↑1.2 / ↓0.8) × (1 + 食材確率アップ合計)（小数第4位まで切り捨て）で食材おてつだいになり、それ以外はきのみおてつだい。食材おてつだいでは食材配列の開いているスロット（Lv.1 / Lv.30 / Lv.60。Lv.50 は2つ）から均等に1つ選び、そのスロットの個数を拾う。
- 満タンになった後は、食材確率に関係なくすべてのおてつだいできのみ（きのみの数Sの効果込み）を拾い、所持数からあふれたきのみはエナジーになる（いつのまに育成）。満タンになったおてつだいであふれた食材は捨てられる。おてつだいキューに残った最大4回分はメインスキルの抽選にだけ使われ、拾うものはきのみになる。
- そのため、1日のきのみ = 1回あたりのきのみ × (おてつだい回数 − 満タンになる前の食材おてつだい回数)。食材確率は満タンになるまでの数回にしか効かず、所持数を増やすと満タンが遅れて食材おてつだいが増えるぶん、きのみのエナジーはわずかに減る。
- 食材配列は入力しない。捕獲時の出現率（食材タイプと同じ）で、配列ごとの値を平均する（たとえばトドゼルガは Lv.60 の候補がすべて4個なので、Lv.30 がオイル×2 かマメミート×3 かだけが効く）。
- 性格のスキル補正はきのみに影響しないので「なし他」として扱う。
- 性格のげんき回復量補正（↑1.2倍 / ↓0.88倍）は、睡眠による回復（100 × 補正、上限100。げんき回復ボーナス持ちは上限105）とげんきオールSの回復量に掛かる（料理の回復には掛からない。回復後のげんきは整数に切り上げ）。回復量が100に届かないときは、前の晩の残り＋回復量が起床時のげんきになる（毎日同じ推移として決める）。たとえばさみしがりのトドゼルガ（ヒーラー1匹）は、起床前の残りが0なので起床時88になる。
- 上位%の分布は、サブスキル（色別抽選・重複なし）と性格25種を共通のモデルで数え上げる。パラメーターごとに別の分布になる。

#### 考慮していないもの

- げんきオールS以外のヒーラースキル（げんきエールSなど）、睡眠中にストックされたヒーラーのスキルが起床時に発動すること、睡眠スコアによる起床時の回復量の違い。
- おてつだいボーナスの5%がほかのメンバーのおてつだいスピード上限35%に含まれるか（既定のほかのメンバーはサブスキルなしなので影響しない）。
- 食材とメインスキルによるエナジー（きのみのエナジーのみで比較）。満タンの間はスキルも抽選されない。
- 日曜夜から月曜朝にかけては満タン後にいつのまに育成へ移行しない（週の最終日だけの例外なので、毎日同じとして計算）。
- イベントボーナスの「通常のおてつだいで拾うきのみ+1」（いつのまに育成では効かない）。

#### 出典

- いつのまに育成・おてつだいキュー: [ポケモンスリープ攻略・検証 Wiki](https://wikiwiki.jp/poke_sleep/)（満タン後は食材確率0%・きのみ確率100%になり、きのみの数Sは効く。キューの残りはスキル抽選のみ）、[ゲームエイト](https://game8.jp/pokemonsleep/584756)
- きのみのエナジー: [RaenonX ポケスリ攻略ツール](https://pks.raenonx.cc/ja/pokedex/365) の Lv.1〜100 の値が上の式と一致することを確認

## スキルタイプ

### ポケモンのデータ

`js/skill/mons.js` の `MONS` にポケモンごとの基礎値（おてつだい時間・スキル確率・食材確率・最大所持数・食材スロットの候補と個数）を持ちます。データは [RaenonX ポケスリ攻略ツール](https://pks.raenonx.cc/ja/pokedex) から 2026年9月25日に取得しました。

- 対象は、とくいが「スキル」で、これ以上進化しないポケモン（伝説・イベント限定の姿を含む54匹）です。
- スキル確率・食材確率は RaenonX の集計値です。集計件数が少ないポケモンは誤差が大きい可能性があります。
- ミュウツーの基礎値は2300秒・スキル2.9%・食材16%・所持数24です。
- 最大所持数は、捕まえた姿の値に、進化1回ごとに5を足した値です（きのみタイプ・食材タイプと同じ）。進化の回数は `evo` に持ち、進化の系統から決めました（伝説・幻・進化しないポケモン・イベント限定の姿は0）。

### 計算モデル

「1日の期待スキル発動回数」に、おてつだいボーナスを持つときはほかの4匹（同じポケモン・サブスキルなし・無補正性格・食材配列は出現率で平均）がおてつだいスピード+5%で増やす発動回数を足し、無補正個体の発動回数で割った比を順位の基準にしています（「おてボのチーム効果」を「含めない」にすると自分の分だけ）。げんき（ヒーラー・料理・性格のげんき回復量補正）とおてつだい回数（小数）はきのみタイプ・食材タイプと同じ規則です。計算は共通の計算モデル（リポジトリ直下の README.md）のとおりで、ポケモンごとに次の値を使います。

- スキル確率 = 基礎値 × 性格(↑1.2 / ↓0.8) × (1 + スキル確率アップ合計) を小数第4位まで切り捨てた値。
- 天井: Ceil[142000 / 基準おてつだい時間] 回続けて不発なら次のおてつだいで発動する（ミュウツーは63回目）。抽選はすべて、天井込みの実質確率 p / (1 − (1 − p)^(天井の回数 + 1)) で数える。
- 日中の受け取りは 常にタップ（ストックは発生しない。おてつだい回数 × 実質確率）/ 3時間ごと（区間ごとに所持数0から睡眠中と同じ規則で追う）。睡眠中は2回までストックでき、所持数が満タンになった後もおてつだいキューに残る4回分までは抽選される（ポケモンスリープ攻略・検証 Wiki）。
- 所持数は、きのみ（1個、きのみの数Sで2個）と食材（食材配列の3スロットから均等に1つ選んだ個数）で埋まる。食材配列は入力せず、配列ごとの結果を出現確率で平均する。
- この計算は [にとよんツール（ポケスリ 個体値計算機）](https://nitoyon.github.io/pokesleep-tool/iv/) のスキル発動回数と、54匹（ストリンダーは姿に合う性格だけ）× Lv.60 / Lv.80 × サブスキル6通り × 性格7通り × パラメーター5通り（食材配列は出現率で平均）の22,260通りを比べた。満タン後のキュー4回の抽選を除くと差は浮動小数の誤差（相対1e-15以下）で、おてつだいボーナスのチーム効果も一致する。キュー4回を数えるぶん、このアプリの値はにとよんツールより中央値2.4%・最大28%多い（所持数の少ないポケモンのチーム効果で最大。ver1.5）。
- 性格はスキル・おてスピ・食材・げんき回復・その他に分類する。上位%の分布はサブスキル（色別抽選・重複なし）と性格25種をすべて数え上げる。
- 統合前のミュウツー版（食材を1/2/4個に固定）の記録は、スキルタイプのミュウツーの記録として一度だけ引き継ぐ。

### にとよんツールに合わせた計算（ver1.5）

おてつだい時間の丸め（秒を切り捨てない）、食材確率・スキル確率の小数第4位の切り捨て、天井の式、天井込みの実質確率での抽選を、にとよんツールに合わせました。満タン後にキューに残る4回の抽選は wiki の記述に従って残します（にとよんツールは数えない）。ver1.4 までの天井カウンタを日をまたいで追う計算はなくなり、分布の計算が速くなりました。分布の保存モデルは10です。

ミュウツー・5枠・チケットあり・ヒーラー1匹（回復18）・チーム効果あり。同じ環境で各3回、新しいプロセスで計算した中央値です（Node.js v22.22.2）。

| 日中の受け取り | ヒーラー発動回数 | ver1.4 | ver1.5 |
|---|---|---|---|
| 常にタップ | 3回 | 6.51秒 | 2.07秒 |
| 常にタップ | 2.5回 | 10.68秒 | 3.28秒 |
| 3時間ごと | 3回 | 10.78秒 | 2.64秒 |
| 3時間ごと | 2.5回 | 18.75秒 | 4.20秒 |

ver1.4 との値の違いと比較の手順は [設計書](../docs/design-v1.5.md) にあります。

#### 考慮していないもの

- メインスキルの効果量（発動回数のみで比較）と、チーム全体の発動回数による確率低下（スキルゲート）。
- フレンドメダルによる1枠目の金確定、自分のスキルによるげんきの回復（げんきチャージSなど）。
- 天井の途中経過の日をまたぐ持ち越し（ゲームではサーバーに記録され引き継がれるが、RaenonX・にとよんツールと同じく天井込みの実質確率で近似する）。
- ストリンダーの姿ごとに付く性格の制限（分布は25種を等確率として数える）。

#### 出典

- 天井の式・実質確率・スキルの数え方: [にとよんツール](https://github.com/nitoyon/pokesleep-tool)（`PokemonIv.pityProcHelpCount`・`calculateSkillRateWithPityProc`・`HelpCount.ts`）、[RaenonX: スキルの天井](https://pks.raenonx.cc/en/docs/view/mechanics/skill-pity)

## ローカルで動かす

リポジトリ直下で簡易サーバーを起動し、`http://localhost:8000/checker/` を開いてください。

```bash
python3 -m http.server 8000
```

`dist/` がなければ分布はすべて画面で計算します。事前計算の分布も試すときは、先にリポジトリ直下で `node scripts/precompute-dist.mjs` を実行して `checker/dist/` を作ります（4コアで2〜3分。確認の手順はリポジトリ直下の [README](../README.md#事前計算した分布)）。
