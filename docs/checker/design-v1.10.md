# ver1.10 設計書

厳選チェッカーで、入力中のサブスキル・性格・食材配列をポケモンごとに端末（`localStorage`）に保存し、そのポケモンを選んだときに戻す。あわせて、初めて開いた人の初期値を「ポケモン未選択」「受け取りは3タイプとも3時間ごと」にする。評価の規則・計算・`MODEL_VERSION`（10）・記録（`iglog`・`bflog`・`sklog`）の形は変えない。画面のバージョンは v1.0 → v1.1。作業の基準は `docs/design-v1.9.md` のあとの `main`。

## 2. 入力の保存

### 2.1 キーと形

- キー: `ckdraft`（既存の `ck` 接頭辞）。1つのキーに全ポケモン分をまとめる。
- 値（JSON）:

```js
{
  "walrein": { "subs": ["bfs", "hs", null, null, null], "nat": "さみしがり", "up": "...", "down": "..." },
  "flygon":  { "subs": [...5], "nat": null, "up": null, "down": null, "arr": [0, 1, null] }
}
```

- キーはポケモンのキー（3タイプで重ならないので、タイプは入れない）。
- `subs` は5枠ぶん（`UNLOCK` の長さ）。未入力は `null`。
- `nat` は性格の名前。`up`・`down` は、性格の名前のない古い記録を戻したときだけ意味を持つ分類（`restoreEntry` と同じ）。
- `arr` は食材タイプのときだけ。
- 入力が全部空（サブスキル5枠 `null`・性格なし・食材配列が `emptyArr` と同じ）のときは、そのポケモンの項目を消す（キーが増え続けないようにする）。「消す」のあとに読み直すと空になるのはこれで満たす。

### 2.2 保存する場所（1か所）

- `state.js` に `saveDraft()` を置き、`ui.js` の `refresh(engines)` の先頭で呼ぶ。入力を変える処理はすべて最後に `refresh` を通るので、保存のし忘れが起きない。確かめた経路:
  - サブスキルのダイアログ（`ui.js:290` の全枠クリア、`304-315` の選択・解除）→ `refresh`
  - 性格（`setNature`・クリア）→ `refresh`
  - 食材配列（`ui.js:236-241`）→ `refresh`
  - 「消す」（`resetSelection`）・「元に戻す」（`restoreSelection`）→ `refresh`
  - 記録を選ぶ（`setMon` → `restoreEntry`）→ `refresh`
- ポケモンを切り替えたときも `refresh` で保存が走るが、直前に読み込んだ内容をそのまま書くだけなので害はない。
- 未選択（`state.mon === null`）のときは何もしない。
- 内容が前回書いたものと同じなら書かない（文字列で比べる）。`refresh` は条件の変更でも走るので、無駄な書き込みを避ける。
- 書き込みの失敗（容量・プライベートブラウズ）は既存の `save` と同じく黙って無視する。

### 2.3 読み込み（`selectMon`）

`selectMon(m)` で、今の「サブスキルと性格は引き継ぐ」をやめ、`ckdraft[m]` から戻す。

- 項目がない → サブスキル空・性格なし・食材配列は `emptyArr(m)`（§6-1）。
- 読み込みの手当ては記録を戻すとき（`restoreEntry`）と同じにし、関数を共通にする:
  - `subs` が配列でない → 5枠とも空。配列なら各枠で `byId[id]` がなければその枠だけ `null`。
  - `nat` が今の性格の名前にない → 性格なし。名前がなく `up`・`down` だけあるときは、そのタイプの分類（`NATL` のキー）に入っている値だけ使い、そうでなければ `null`。
  - `arr` は長さが今のスロットの数と違えば、まるごと `emptyArr`。長さが合えば各枠で「0以上・候補の数未満の整数」でなければその枠を `emptyArr` の値（候補1つの枠は 0、ほかは `null`）。
  - 「その部分だけ空」の結果、手前の枠が空いて後ろの枠が埋まっている並び（例 `[a, null, c]`）になりうる。これは今の画面でも記録の復元で起こりうる状態で、判定は出ず、入力すれば埋まる。詰め直しはしない（記録と同じ扱いにそろえる）。
- `ckdraft` が JSON でない・オブジェクトでない・`m` の項目がオブジェクトでない → その項目がないのと同じ。読み込みで例外は外に出さない（既存の `load` が `try` で包んでいる）。
- 壊れた項目は書き直さない。次にそのポケモンで `refresh` が走ったときに、正しい形で上書きされる。

### 2.4 そのほかの決まり

- 記録を選んだとき（`renderLog` の `restore`）: `setMon` で前回の入力を一度読み込み、すぐ `restoreEntry` で置き換え、`refresh` で保存する。前回の入力は記録の内容で上書きされる（指示どおり）。
- 狙い食材（`igtarget`）は今までどおり別のキーで、変えない。
- 記録（`iglog`・`bflog`・`sklog`）・事前計算の分布・IndexedDB の分布には触れない。

## 3. 初期値

### 3.1 ポケモン（未選択から）

`loadSettings` の順番:

1. `?mon=` が今のポケモンにある → そのポケモン。
2. なければ保存したポケモン（`ckmon`、なければ統合前の `igmon`・`bfmon`）→ そのポケモン。
3. どれもない → `state.type = DEFAULT_TYPE`（きのみ）、`state.mon = null`。

- `state` の初期値も `mon: null` にする。
- 未選択のときは `rememberMon`・`save(KEYS.mon)` をしない（`null` を保存しない。保存済みの値を上書きしない）。
- タブを切り替えたとき（`setType`）: `lastMonOf(type)` が、`ckmons[type]`（統合前の `igmon`・`bfmon` も）にそのタイプのポケモンがなければ `null` を返す（今は `DEFAULT_MON`）。`null` なら `state.type = type`・`state.mon = null`・`arr = []`・`target = null`・サブスキルと性格を空にする。
- `?mon=`・保存したポケモン・記録から選んだとき・ポケモンを選ぶダイアログで選んだときは、今までどおり `setMon`。
- `syncUrl`: 未選択なら `?mon=` を外す（`history.replaceState(null, '', location.pathname)`）。

### 3.2 受け取り

| | 今 | 変更後 |
|---|---|---|
| きのみタイプ `tap` | `'none'`（なし・いつ育） | `'3h'` |
| 食材・スキルタイプ `ingTap` | `'always'`（常にタップ） | `'3h'` |

- `state` の初期値と `loadSettings` の `loadSetting('tap', …)`・`loadSetting('ingTap', …)` の既定、範囲外の値のときの戻し先の3か所をそろえる。
- 保存済み（`cktap`・`ckingtap`）があればそちらを使う。
- 詳細のダイアログの「初期値に戻す」（`paramReset`）は回復量・発動回数・フィールドボーナス・好きなきのみだけを戻し、受け取りは触らない（確認済み。変更なし）。

## 4. 未選択の画面

育成シミュレーター（`exp/js/main.js` の `renderMon`）と同じ形の、「?」とボタン1つのカードにする。

- `isComplete`・`canRate`・`targetClosed`・`env` など `monData()` を使うものは、`state.mon` が `null` で呼ばれても例外を出さないよう `hasMon()` を先に見る（保険）。

### ブラウザ（Playwright、390×844 タッチと 1280×800）

1. `localStorage` を空にして開く → ポケモン未選択のカード、受け取りは3タイプとも「3時間ごと」が押された状態。コンソールのエラー0件。Worker への依頼（`postMessage`）が0件。
2. 未選択のまま、タブ3つ・条件の変更・詳細・記録のダイアログを開いて閉じる → エラー0件。
3. ポケモンを選び、サブスキル・性格（食材タイプは食材配列も）を入れて読み直す → 戻る。
4. 別のポケモン（別タイプも）で入力 → 元のポケモンに戻すと、それぞれの入力が戻る。
5. 育成シミュレーターでそのポケモンを選び「厳選チェッカーで見る」→ 前回の入力が戻る。
6. 「消す」→ 読み直す → 空。「消す」→「元に戻す」→ 読み直す → 戻した内容。
7. 記録を選ぶ → 読み直す → 記録の内容。
8. 前の版の `localStorage`（`ckmon`・`ckmons`・`cktap`・`ckingtap`・`cklv`・`iglog` など）を入れて開く → そのポケモン・設定・記録がそのまま。
9. ログイン画面とフッターが v1.1。

## 6. 迷った点・前提を置いた点

1. **保存のないポケモンを選んだとき、入力を引き継ぐか空にするか。** 今は「サブスキルと性格は引き継ぐ」。ポケモンごとに保存するなら、引き継ぐとそのまま新しいポケモンの保存になり、「そのポケモンの前回の入力」と区別がつかなくなる。**空にする**案にした。引き継ぎを残したい場合は言ってください。
2. **未選択のときにサブスキル・性格を入れられるか。** 保存はポケモンごとなので、入れても保存先がない（選んだ瞬間に消えるか、選んだポケモンへ持ち込むかの決まりが要る）。**隠す**案にした。
3. **未選択のときに記録の一覧の確率を計算するか。** 「ポケモンがないときに分布を呼ばない」に合わせ、未選択の間は記録の一覧も無補正比だけ出して確率は「—」のまま（ポケモンを選べば出る）にする。ここは、未選択でも一覧の確率は出す（`logNeeds` だけは読む）方が便利かもしれない。指示の文言を優先して、出さない方にした。
4. **初回のタブ。** 未選択でもタブはどれか1つ選ばれている必要があるので、今の `DEFAULT_TYPE`（きのみ）にする。
5. **`up`・`down` を保存するか。** 性格の名前のない古い記録を戻したときの入力を保てるよう、保存する。

## 7. 事前計算の範囲（決定：案A）

事前計算（`precomputed.js`）は受け取りを `TYPES[type].TAPS[0]`（きのみ `none`、食材・スキル `always`）で作っていた。初期値を `3h` にすると新しい人の既定の条件が範囲外になるので、レビューで次の案から **A** に決めた。

- **A（採用）** 事前計算の受け取りを、新しい既定の `3h` にする。件数は1,554件のまま、CI の時間も同じ。前の既定（`none`・`always`）を保存している今の人は範囲外になり、その場の計算に戻る。
- B 受け取りの2通りとも事前計算する（3,108件、CI と公開物がおよそ2倍）。
- C 事前計算は変えない（新しい人は毎回計算）。

実装:

- 受け取りの初期値を `types.js` の `DEFAULT_TAP = '3h'` にまとめ、`state.js`（初期値・`loadSettings`）と `precomputed.js`（`preEnv`）の両方がこれを使う。ずれないよう1か所にした。
- `tests/check-precomputed.mjs` の「範囲外の条件」の受け取りを、`'3h'` からそのタイプの `TAPS[0]`（前の既定）に変えた。「画面の既定の条件が範囲に入る」はそのまま通る。
- 分布の中身・キーの形・`MODEL_VERSION` は変えない（`tap` はもともと条件の一部としてキーに入っている）。
- `TAPS` の並び（`['none', '3h']` など）は画面のボタンの順でもあるので、並べ替えでは対応しない。

## 8. 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| ポケモンごとに別のキー（`ckdraft:walrein` など） | キーが最大125個に増え、掃除や一覧が面倒。1つのキーでも大きさは数KB |
| 入力を変える関数（`setNature`・サブスキルのクリックなど）それぞれで保存 | 書き忘れが起きやすい。`ui.js` が `state.subs` を直接書き換える箇所もある。`refresh` 1か所の方が確実 |
| `setTimeout` でまとめて保存（間引き） | 書き込む前にページを閉じると消える。中身が同じなら書かないので、回数の心配は小さい |
| 未選択の代わりに「既定のポケモン＋目印」 | 指示は未選択から。画面のどこで何が出るかが曖昧になる |
| 未選択のとき判定の欄を「—」のまま全部出す | 意味のない数値欄が並び、何をすればいいか分かりにくい。育成シミュレーターと同じく、まず選ばせる |
| 保存する内容に日時や版の番号を付ける | 読み込みは記録と同じく項目ごとの検査で足りる。形を変えるときは別のキーにする |
