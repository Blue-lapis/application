# ver1.12 設計書

食材タイプの評価を「狙い食材の個数」（今まで）と「エナジー」で切り替えられるようにする。狙い食材の個数だけで比べると、きのみS（きのみの数S）はきのみで所持数を早く埋めるぶんわずかにマイナスになり、エナジーで見たいときの評価と合わない。エナジーは、すべての食材ときのみの1日のエナジーの合計で比べる。画面のバージョンは v1.4 → v1.5。「狙い食材の個数」の計算・条件の形・`MODEL_VERSION`（10）・記録の形は変えない。

## 2. 計算

- おてつだい回数・げんき・所持数の遷移は今までと同じ（共通の `fillCurve`）。所持数の遷移はもともときのみの期待個数（`berries`。満タン後のおてつだいはきのみ）を持っているので、区間ごとにそれを足す。「常にタップ」の日中は 回数 × 1回の個数 × (1 − 食材確率)。
- 評価の値 = Σ 食材の個数 × 食材1個のエナジー ＋ きのみの個数 × きのみ1個のエナジー（`berryEnergy(基礎, Lv)`、きのみタイプと同じ式）。
- 料理の倍率: 食材のエナジーに ((1＋レシピボーナス) × (1＋レシピレベルのボーナス) × 0.8 ＋ 0.2) を掛ける（にとよんツールの `PokemonStrength` と同じ。レシピボーナス0%は1倍）。レシピボーナスは選択肢（0・19・20・21・25・35・48・61・78%）、平均レシピレベルは1〜70の整数で、既定は 25%・Lv.30（1.81倍）。表は `energy.js` の `RECIPE_LEVEL_BONUS`。設定は `ckrecipebonus`・`ckrecipelv`、条件には `recipeBonus`・`recipeLevel` を入れる（食材ときのみの比重が変わるので分布も変わる）。
- 掛けないもの: フィールドボーナス・好きなきのみ（きのみ）。
- 基準: **同じ食材配列**の無補正個体（サブスキルなし・無補正性格）。`reference(env, arr)`・`baseMetric(env, arr)` に食材配列を渡す（エナジーのときだけ使う。「狙い食材の個数」は今までどおり、狙い食材が最も多い配列）。共通の基準（エナジーが最も高い配列）で割ると、エナジーの高い食材が混ざる配列（ABC など）がサブスキルと関係なく有利になるため。どの配列でも無補正個体は1倍になる。
- チームへの効果: ほかの4匹を自分と同じ食材配列として、おてつだいスピード+5%で増えるエナジー（`team(m, env, arr)`）。
- 分布: **同じ食材配列の個体だけを母集団にする**。条件に食材配列 `arr`（開いている枠の候補の番号をつないだ文字列、例 `'012'`）を入れ、`buildDist` には食材配列をその1つに固定して（確率1）渡し、サブスキル・性格だけを数え上げる。同等以上の確率・平均何匹に1匹・順位はどれも、その配列の個体の中での値になる。配列の違う個体（AAA と AAC など）は比べない。食材配列がそろうまでは分布を求めない（`state.js` の `distReady`、`ui/dist.js`）。
- 食材配列が決まっていないとき（表示だけ）は、エナジーが最も高い配列を基準に出す。

## 3. 条件と分布の保存

- エナジーの条件は `{ lv, N, camp, mon, by: 'energy', arr, heal, tap, team, healAmt, healTimes, recipeBonus, recipeLevel }`（`target` なし）。狙い食材を変えても同じ分布を使い、食材配列ごとに別の分布になる。
- 「狙い食材の個数」の条件は以前とまったく同じ形にし、IndexedDB に保存した分布・事前計算の分布のキーを変えない。
- エナジーの条件は `isPrecomputed` の範囲外（項目が違う）なので、Worker が計算する。5枠でも1秒ほど（Node で Lv.80 が約0.8秒）なので、事前計算はしない。

## 4. 確かめたこと

- `tests/check-ingenergy.mjs`: データがそろっていること、エナジーではどの食材配列でも無補正個体が1倍になること、評価の値と表示の値（`daily`）が一致すること（1,504ケース）、「常にタップ」の日中のきのみの個数、エナジーの評価が狙い食材によらないこと、「狙い食材の個数」の条件のキーが以前と同じこと、きのみSがエナジーでだけ無補正比を上げること（40匹）、分布の合計が1。
- 既存のテスト（`check-segs`・`check-dist`・`check-nature`・`check-boost`・`check-exp`・`check-draft`・`check-version`）が通ること。
- ヘッドレス Chromium（幅390px）で、切り替えると帯・結果・くわしい数値がエナジーに変わり、戻すと元の値になること。Lv.50 で Lv.60 の枠だけに出る食材を狙いにしていても、エナジーでは評価できること。コンソールにエラーがないこと。
