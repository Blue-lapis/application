# ver1.4 設計書

[要件定義](requirements-v1.4.md) に沿って、スキルタイプの分布計算を高速化する。評価の規則は ver1.3 のまま。作業の基準は `03d095d60713622cac9f9cfa86e44f308e6b233b`。

## 1. 変えたファイル

| ファイル | 変更 |
|---|---|
| `js/calc.js` | `runSegs` の状態配列・リングの参照・区間の終端を最適化 |
| `checker/js/distcache.js` | `MODEL_VERSION` を8に |
| `tests/check-segs.mjs` | 天井・ストック・キュー・小数回数の独立した参照計算 |

| `tests/compare-dist.mjs` | 保存した2つの分布の行数・無補正比・確率・累積確率を比較 |

3タイプの個別エンジン、データ、画面、Worker の数は変えない。

## 2. 天井カウンタの高速化

### 2.1 ストック0回と1回の配列をまとめる

区間の始めにストックは0回。不発回数を `j`、区間内で済んだ抽選を `i` とする。

| 状態 | 不発回数の範囲 |
|---|---|
| 区間内でまだ発動していない | `j >= i`。天井に達すると発動するので `i >= ceil` では残らない |
| 区間内で1回発動した | `j < i`。発動した抽選で0に戻る |
| 区間内で2回発動した | 抽選を止め、`j = 0` の確率を `z` に持つ |

0回と1回の状態は同じ `j` に重ならないので、リング配列を1本にまとめる。天井の直前の要素は、`i < ceil` なら0回の状態、その後なら1回の状態として読む。区間の終わりには従来どおりストックを回収する。

配列の加算・初期化・正規化が減る。確率の加算順・共通倍率の正規化のしきい値は変えない。

### 2.2 リングの参照

- 1回進めるときの先頭は、`h === 0 ? ceil - 1 : h - 1` で求める。
- `collect` はリングの折り返し位置で2つのループに分ける。内側のループで `% ceil` を計算しない。
- 各要素へ掛ける確率・倍率の順序は変えない。

### 2.3 確率0の末尾

抽選回数の分布 `P` の末尾から、厳密に0の部分だけを除いて状態を進める。以後は結果へ足される確率がないため、区間の終わりの分布は同じ。小さい正の確率は省かない。睡眠中の抽選回数・満タン確率の表示には元の分布を使う。

### 2.4 変えないもの

天井の定義、ストック2回、満タン後のキュー4回、小数回数の混合、`CHAIN_TOL = 1e-12`、`CHAIN_MAX_DAYS = 200`、区間・食材配列・性格・サブスキルの数え方。初期分布は毎回不発0回から始め、別の計算の収束値を持ち込まない。

## 3. 検証

- `node tests/check-dist.mjs`: 3タイプ各2条件の分布整合性テストが通過。
- `check-segs.mjs`: 505ケース。単純な状態遷移（ストック数×不発回数）と比べる。所持数は小さな全経路列挙とも比べる。天井1・2・3・8・50、確率0〜1、小数・0回、2回ストック、満タン後4回、共通倍率の正規化を含む。逆順で再計算しても同じ。
- `compare-values.mjs`: 125匹 × 条件4 × サブスキル4 × 性格4 = 8,000件。きのみ1,984件・食材2,560件・スキル3,456件。変更前後の無補正比・自分の値・無補正個体の値の最大絶対差0。
- 分布と時間: 次章。分布の行数・無補正比・確率・同等以上の累積確率を比べる。

## 5. 再確認する手順

Node.js で実行する。比較先には変更前のコミットを指定する。

```sh
git worktree add --detach ../application-baseline 03d095d60713622cac9f9cfa86e44f308e6b233b
node tests/check-segs.mjs
node tests/check-dist.mjs
node tests/compare-values.mjs ../application-baseline
node tests/bench-dist.mjs ../application-baseline always 3 /tmp/before.json
node tests/bench-dist.mjs . always 3 /tmp/after.json
node tests/compare-dist.mjs /tmp/before.json /tmp/after.json
```

`bench-dist.mjs` の `always` を `3h`、`3` を `2.5` に変え、4条件をそれぞれ3回実行する。変更前後を交互に実行し、同時に重い処理を動かさない。最後の引数でポケモンのキーも指定できる。時間は Node.js の計算部分であり、ブラウザ上の表示待ち時間そのものではない。
