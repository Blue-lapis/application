# ver1.8 設計書

きのみタイプの詳細設定に「フィールドボーナス」と「好きなきのみ（エナジー2倍）」を足し、1日のエナジーをゲーム内の値に近づける。無補正比・同等以上の確率・順位・分布・記録は ver1.7 と同じ。作業の基準は `577406e`。

## 1. 画面

画面イメージ: https://claude.ai/artifact/F6yQxvDUhhtQHgoRkR62YE

- **詳細のダイアログ**（きのみタイプだけ、`data-for="berry"`）: ヒーラーの下に「きのみのエナジー」。
  - フィールドボーナス（%）: 整数 0〜85 の入力欄（33 のような値も手入力できる）と −／＋（5の倍数に揃えて5%ずつ。33 なら＋で35・−で30。端で止まる）。範囲外・小数は受け付けず、今の値に戻す（回復量と同じ）。
  - 好きなきのみ: OFF / ON（2倍）の切り替え。ラベルに今のポケモンのきのみ名（「ピクシーのきのみ（モモンのみ）を好きなきのみとして扱う」）。
  - 「初期値に戻す」でボーナス0%・OFF にも戻す。
- **性能の欄の要約**: 既定でないときだけ「フィールドボーナス+50%・好きなきのみ」を足す。
- **結果**: 1日のエナジー・日中・睡眠中・自分のきのみエナジー・チームへの効果・無補正の個体に補正を掛ける。「きのみ1個のエナジー」の行に「112にフィールドボーナス+50%・好きなきのみを掛けて切り上げ」と内訳を出す。

## 2. 計算

- `boostedEnergy(energy, bonus, fav) = ceil(ceil(energy × (100 + bonus) / 100) × (fav ? 2 : 1))`（`checker/js/berry/calc.js`）。
  - 1個ごとの切り上げはにとよんツール（`src/util/Berry.ts` の `getBerryStrength`）と同じ。ただし向こうは `1 + bonus / 100` を浮動小数で掛けるので、100 × 1.1 のような値が1大きくなることがある。こちらは整数で割って避ける。
  - 好きなきのみの倍率は `FAV_MUL = 2`。エキスパートモードの2.4倍は扱わない。
- 自分・ほかの4匹・無補正の個体は同じポケモン・同じレベルなので、1個のエナジーは同じ値になり、比率 `k = boosted / energy` が全部に等しく掛かる。無補正比は変わらない。
- そのため `env`・`envKey`・分布の保存のキー・`MODEL_VERSION` は変えない。エンジン（`metric`・`score`・分布）は補正なしのまま、`renderBerryStats` で `k` を掛ける。

## 3. 状態

| キー | 値 | 既定 |
|---|---|---|
| `ckfieldbonus` | 整数 0〜85（`PARAM_LIMITS.fieldBonus`） | 0 |
| `ckfav` | 真偽 | false |

- `state.fieldBonus`・`state.fav`。不正な保存値は既定に戻す。ポケモンを切り替えても残す（ポケモンごとには覚えない）。
- 記録（`bflog`）には持たない（保存するのは無補正比）。

## 4. 確認

- `node tests/check-boost.mjs`: 既定で従来の値と一致、切り上げの範囲と浮動小数の境界（100 × 110% = 110）、補正の比率を掛けても無補正比が同じ。Pages の公開前のテストに追加。
- ブラウザ: ピクシー Lv.60 でボーナス50%・好き ON にすると 18,286 → 54,858（3倍）。範囲外（86）・小数（33.5）は受け付けない。33 は受け付け、＋で35・−で30、85で止まる。再読み込み後も残る。食材タイプでは要約・ダイアログに出ない。
