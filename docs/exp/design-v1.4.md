## 3. カード「厳選チェッカーで見る」

### 3.1 判定（`exp/js/link.js`）

```js
import { MONS as BERRY } from '../../checker/js/berry/mons.js';
import { MONS as ING } from '../../checker/js/ingredient/mons.js';
import { MONS as SKILL } from '../../checker/js/skill/mons.js';
// 厳選チェッカーで開くリンク。チェッカーが ?mon= を読むときの typeOf と同じく、3タイプの MONS にあるかで決める。
// 開けないときは href を null にして、理由を sub に入れる。
export function checkerLink(mon) {
  if (!mon) return { href: null, sub: 'ポケモンを選ぶと開けます' };
  if (![BERRY, ING, SKILL].some((m) => Object.hasOwn(m, mon))) return { href: null, sub: 'このポケモンは厳選チェッカーに未対応です' };
  return { href: `../checker/?${new URLSearchParams({ mon })}`, sub: null };
}
```

| 見る値 | 条件 | 結果 |
|---|---|---|
| `st.mon` | `''`（未選択・「選ばない」） | 無効。「ポケモンを選ぶと開けます」 |
| `st.mon` | 空でなく、BERRY・ING・SKILL のどの `MONS` にもない | 無効。「このポケモンは厳選チェッカーに未対応です」 |
| `st.mon` | それ以外 | 有効。`../checker/?mon=<st.mon>`。小さい文字は「<名前>の個体を判定」 |

- 判定は、チェッカーが `?mon=` を読むときの `typeOf`（`checker/js/types.js:19`、`Object.hasOwn(TYPES[t].MONS, mon)`）と同じ条件にする。`TYPES[t].MONS` は各タイプの `mons.js` の `MONS` そのもの（`constants.js` が再 export）なので、チェッカーが開けるかどうかと食い違わない。
- `typeOf` を直接 import しないのは、`types.js` が3タイプの計算エンジン（`calc.js`）まで読み込むため。育成のページは今も3つの `mons.js` だけを読んでいる。
- 性格・レベルは渡さない（育成の性格は3択で、チェッカーの25種類に戻せない）。
- 名前は `ALL_MONS[st.mon].name` をそのまま出す（`パンプジン(ちゅうだましゅ)の個体を判定`）。`esc` を通す。

### 3.2 HTML

結果のカード（`#outSec`）のすぐ下、「目標レベル別」（`#lvx`）の上に入れ物を置き、中身は `main.js` が入れる。

```html
<!-- 厳選チェッカーへ（チェッカーの「育成日数を見る」と同じ部品）。ポケモンだけを渡す。 -->
<div class="tocheck" id="toChecker"></div>
```

有効のとき（チェッカーの `#toExp` と同じ並び。アイコンを天秤にする）:

```html
<a class="toexp" href="../checker/?mon=butterfree">［天秤 20px］<span><b>厳選チェッカーで見る</b><small>バタフリーの個体を判定</small></span>［＞ 14px］</a>
```

無効のとき:

```html
<div class="toexp" aria-disabled="true">［天秤］<span><b>厳選チェッカーで見る</b><small>ポケモンを選ぶと開けます</small></span>［＞］</div>
```

- `<a>` と `<div>` を入れ替えるので、`#toChecker` の `innerHTML` を作り直す。`<div>` には `href`・`tabindex`・クリックの処理を付けないので、押しても何も起きず、Tab でも止まらない。
- 文言は `<small>` に出すので、スクリーンリーダーには「厳選チェッカーで見る ポケモンを選ぶと開けます」と読まれる。

### 3.3 見た目（`exp/css/exp.css`）

`.toexp` は `theme.css` のものをそのまま使う。チェッカーでは `section.mon` の中の1行（上に区切り線）だが、こちらは単独のカードなので、入れ物を `.lvx` と同じ枠にする。

```css
/* 厳選チェッカーへ。チェッカーの .toexp を、.lvx と同じ枠の1枚のカードにする。 */
.tocheck{margin:0 0 14px;border:1px solid var(--line);border-radius:20px;background:var(--card);overflow:hidden}
.tocheck .toexp{border-top:0}
.tocheck .toexp[aria-disabled="true"]{opacity:.45;cursor:default}
```

- 無効の薄さ（`opacity:.45`）は `theme.css` のサブスキルの枠・ダイアログのタブの `:disabled` と同じ値。
- 天秤の色は `.toexp>svg:first-child` の `--psy-ink`（ポケモンのタイプの色。未選択は食材の緑）。

## 4. 再描画のタイミング

- `show()` の中で `renderMon()` の直後に `renderToChecker()` を呼ぶ。`st.mon` が変わる道（ダイアログで選ぶ・「選ばない」・URL の `?mon=`・起動時の確かめ）は、どれも最後に `update()` → `show()` を通るので、漏れなく作り直される。
- `show()` は数の入力のたびにも呼ばれるので、前に描いた `st.mon` を覚えておき（`shownCheck`）、変わったときだけ `innerHTML` を作り直す（チェッカーの `renderHeader` の `shownHeader` と同じやり方）。初回は `null` なので必ず描く。

```js
// 厳選チェッカーへのカード。ポケモンが変わったときだけ作り直す。
let shownCheck = null;
function renderToChecker() {
  if (st.mon === shownCheck) return;
  shownCheck = st.mon;
  const { href, sub } = checkerLink(st.mon);
  const body = `${SCALE}<span><b>厳選チェッカーで見る</b><small>${esc(sub ?? `${ALL_MONS[st.mon].name}の個体を判定`)}</small></span>${chev}`;
  $('toChecker').innerHTML = href ? `<a class="toexp" href="${esc(href)}">${body}</a>` : `<div class="toexp" aria-disabled="true">${body}</div>`;
}
```

## 8. 迷った点・前提を置いた点

どれもレビュー（画面イメージ）で、このままでよいと確かめた。


- **対象外のポケモン（ミュウなど）は、今の画面からは選べない。** 育成のダイアログは3タイプのポケモンしか出さず（`GROUPS`）、URL・保存から来たキーも起動時に `ALL_MONS`（＝3タイプ）になければ消す（`main.js:380`）。ミュウ・ダークライは `data.js` のコメントのとおり「経験値タイプを直接選ぶ」扱いで、`st.mon` は `''` になる。そのため2つ目の条件は今は起きず、将来育成側にだけポケモンを足したときの守りになる。ブラウザでの確認はテスト（§7）で代える。
- **育成の `#schedTop`（日程）の場所。** 指定の並び（右から テーマ・天秤）に日程が出てこないので、今と同じく天秤の左に残すことにした（右から テーマ・天秤・日程）。日程を左にずらすか、ヘッダーから外すかは指定があれば変える。
- **育成のログイン画面の見出し。** 今は月（チェッカーの絵の流用）だが、「育成は今のカレンダー」「ログイン画面も同じ絵」に合わせ、育成のログイン画面もカレンダーにする前提にした。
- **カードの置き場所。** 「結果パネルの下」を、結果のカード（`#outSec`）のすぐ下・「目標レベル別」の上と読んだ。結果を見た直後に目に入り、広い画面でも右の列の上のほうに来る。
- **無効のときの ＞。** 構造をそろえるため残し、カードごと薄くする。
- **小さい文字の名前。** 姿の名前も含めてそのまま出す（`パンプジン(ちゅうだましゅ)`）。ポケモンのカードのように2行に分けない。
- 育成のテーマのボタンには、チェッカーにある `title` がない。今回の範囲外として変えない。

## 9. 考えたが採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 無効のときも `<a>` のままにし、`href` を外して `aria-disabled` を付ける | 指定どおり `<div>` にした。`href` のない `<a>` はフォーカスの扱いがブラウザで揺れ、押せそうに見える |
| 判定を `main.js` の中に書く | ブラウザでは2つ目の条件を起こせないので、Node のテストで確かめられるよう `link.js` に分けた。`calc.js` は計算だけの約束なので入れない |
| 判定にチェッカーの `typeOf` を import する | 同じ関数を使えるが、`types.js` が3タイプの計算エンジンまで読み込み、育成のページが重くなる。同じ条件（3つの `MONS` にあるか）を `link.js` に書いた |
| 判定を育成の `ALL_MONS`（または `groupOf`）で行う | 今は同じ結果になるが、`main.js` の中にあると Node のテストから呼べない。`link.js` で `mons.js` を直接見る |
| `show()` のたびに作り直す | 数を入力するたびにリンクの要素が入れ替わり、押そうとしたときに要素が変わる。ポケモンが変わったときだけにした |
| チェッカーの `.toexp` を `section` の中の1行として置く（区切り線つき） | 育成の結果の列には入れられる `section` がなく、新しい `section` に1行だけ入れると余白が二重になる。`.lvx` と同じ枠の入れ物にした |
| 性格・レベルを渡す | 指定のスコープ外（育成の性格は3択で、チェッカーの25種類に戻せない） |
| 天秤をよくあるアイコンセットからそのまま使う | ライセンス表記が要る。線幅・丸端だけそろえて自前で描いた |
