# 育成日数シミュレーター v1.0 要件定義

ポケモンを目標のレベルまで育てるのに何日かかるかを、**アメ・ゆめのかけら・睡眠EXP・ゴンベのおひるね島**を組み合わせて計算する。育て方（ルート）ごとの日数を並べ、どれが早いか、アメとゆめのかけらをいくつ使うかを見られるようにする。

厳選チェッカー（`checker/`）とは別の計算で、チェッカーの計算・保存データは変えない。アプリはスマートフォンでの操作が多いので、画面はスマートフォンを基準に考える。

## 1. 目的と範囲

- 目的: 「今のレベルから目標のレベルまで、何日で届くか」を、ルートごとに比べて出す。
- 対象: レベル上限（現行 Lv.70）までの全レベル、4つの経験値タイプ（600・900・1080・1320）、性格のEXP補正（上昇・なし・下降）。
- 進化（アメで進化させる分）は数えない。進化に要るアメは、使えるアメの数から利用者が差し引いて入れる。

## 2. 使う人と場面

- 厳選が終わった個体を、どこまで・いつまでに育てるか決めたいとき。
- 今週おひるね島に預けるか、チームで寝かせるか迷ったとき。
- Lv.50（サブスキル3枠目）や Lv.60（食材3枠目）にいつ届くかを知りたいとき。

## 3. ゲームの仕様（計算の前提）

数値はにとよんツール（`nitoyon/pokesleep-tool` の `src/util/Exp.ts`・`Nature.ts`、`7daacf8`、2026年9月30日）から取り、wiki（Pokémon Sleep 攻略・検証 Wiki）の表と照らした（§7）。

### 3.1 必要EXP

- 累計EXP表（600タイプ、Lv.0〜70）を持ち、経験値タイプの倍率（600: 1、900: 1.5、1080: 1.8、1320: 2.2）を掛けて四捨五入する。
- Lv.a → Lv.b の必要EXP = round(累計[b] × 倍率) − round(累計[a] × 倍率)。
- 今のレベルで貯まっているEXP（ゲームの「次のレベルまで あと ○○」から逆算）を差し引く。

### 3.2 アメ

| 使う時点のレベル | 1個のEXP（性格なし） | 上昇 | 下降 |
|---|---|---|---|
| Lv.1〜24 | 40 | 47 | 33 |
| Lv.25〜29 | 35 | 41 | 29 |
| Lv.30〜 | 25 | 30 | 21 |

- レベルごとに、そのレベルを上げるのに要る個数（切り上げ）を使い、あまったEXPは次のレベルに持ち越す。
- ゆめのかけらは、アメ1個ごとに「上がった先のレベル」で決まる量（Lv.2〜70 の表）を払う。経験値タイプでは変わらない。

### 3.3 アメを先に使う

- 1個あたりのEXPは低いレベルほど多く、ゆめのかけらは低いレベルほど少ない。睡眠EXP・おひるね島はゆめのかけらを使わない。
- そのため、**手持ちのアメは最初にまとめて使う**のが、日数でもゆめのかけらでも最もよい。どのルートも「アメを先に使い、残りを睡眠かおひるね島で稼ぐ」とする。
- ゆめのかけらの上限を入れたときは、その範囲で使える分だけ使う。

### 3.4 アメブースト（D3）

- アメのEXPが2倍になり、ゆめのかけらはミニで4倍・1日50個まで、ホリデーで5倍・1日500個まで（イベントで変わる）。
- 1日の上限は全ポケモンで共有。上限があると「アメを先にまとめて使う」が1日で終わらなくなるため、v1.0 では扱わない案を推す。

### 3.5 睡眠EXP

- 1日の睡眠スコア = min(round(睡眠時間（分）÷ 510 × 100), 100)。1日2回まで計測でき、合計は100まで。
- 1日の基本EXP = round(スコア × (1 + 0.14 × 睡眠EXPボーナスの数))。ボーナスはチームの中の数で、0〜5。
- その日のEXP = floor(基本EXP × 日の倍率 × 性格)。性格は上昇 1.18、なし 1、下降 0.82。
- 預けているポケモンがチームにいるあいだだけ貯まる。

### 3.6 日の倍率（グッドスリープデー・せいちょうのおこう）

グッドスリープデーは、満月の日を中心にした3日間。言葉は「グッドスリープデー＝3日間」「満月の日＝そのまん中の日」で統一する。

| 日 | 倍率 | おこうを使った日 |
|---|---|---|
| ふつうの日 | 1 | 2 |
| グッドスリープデーの1日目・3日目 | 2 | 4 |
| グッドスリープデーの満月の日（2日目） | 3 | 6 |

- おこうの使い方は「使わない／グッドスリープデーの満月の日だけ／グッドスリープデーの3日間／2日に1回（ふつうの日は×1.5の平均）／毎日」から選ぶ（にとよんツールと同じ5通り）。
- 満月の日の見込みは、満月の時刻（Meeus『Astronomical Algorithms』49章の式。暦の値と1分以内で一致）を日本時間にした日付。試作版 v0.2 までの月齢の近似は、満月の日が2日続いて4日間のグッドスリープデーになることがあったので、v0.3 で変えた。
- 実際の日程は公式のお知らせで決まるので、日程ごとに前後3日までずらすか、なしにできる（D4）。直した内容は端末に保存する。

### 3.7 ゴンベのおひるね島

- 1日150EXP。おひるねリラックスチケットを使うと1日600EXP（チケット1枚で7日、預けている間だけ減る）。
- 性格は上昇（1.18）だけ効き、下降は効かない。
- 貯まるEXP = floor(1日のEXP × 性格 × 経過分 ÷ 1440)（1分ごと）。
- **7日未満で引き取ると半分**（チケットの分も）。
- 預けている間は、アメが使えず、睡眠EXP・おこう・イベントのボーナスも入らない。
- ものひろいで拾うアメ・ゆめのかけらは、量が決まらないので数えない（§9）。

## 4. 計算のモデル

### 4.1 共通

1. 手持ちのアメを、今のレベルから順に使う（§3.3）。目標に届いたらそこで止め、あまったアメを出す。
2. 届かなければ、残りのEXPをルートごとに日数で稼ぐ。
3. 1日ずつ（おひるね島は1分単位で）EXPを足し、目標の累計に届いた日を到達日とする。レベル上限であふれた分は数えない。

### 4.2 ルート（D1）

| ルート | 中身 |
|---|---|
| A. 睡眠のみ | アメの後、チームに入れて毎日寝る |
| B. おひるね島のみ | アメの後、おひるね島に預ける。7日未満で届くときは「7日待つ」と「半分で引き取る」の早いほう |
| C. 組み合わせ（案2のとき） | アメの後、日ごとに「その夜はチームで寝る」か「島に7日以上預ける」かを選んだ予定のうち、最も早く届くもの |

- 同じポケモンを、同時に島とチームに入れることはできないので、C は期間ごとに切り替える。島は7日以上預けて引き取る（最後に届くときだけは、7日未満で半分で引き取るのも候補）。
- 求め方は動的計画法。日ごと・チケットの残り日数ごとに、得られる最大のEXPを持つ。島に預けるのは7〜13日を1つの単位にし、14日以上はつないで表す（1日あたりのEXPは整数なので、つないでも切り捨てで減らない）。最後は、どの日から預けても届く時刻（半分で引き取るか7日待つか）と、睡眠で届く日の、最も早いものを選ぶ。
- 試作版 v0.1 は「始める日から7日ごとに、睡眠と島の多いほう」にしていたが、グッドスリープデー・満月が7日の区切りをまたぐと、どちらの週も島が選ばれて取りこぼし、島から7日ごとに引き取るため「島のみ」より遅くなることもあった。v0.2 で上の方式に変えた。
- テスト（`tests/check-exp.mjs`）で、島を7〜30日のどの長さでも預けられる総当たりの最短と一致すること、どの開始日でも睡眠のみ・島のみより遅くならないことを確かめる。

## 5. 入力

| 項目 | 値 | 既定 |
|---|---|---|
| ポケモン（D2） | 一覧から選ぶ。経験値タイプが決まる | — |
| 経験値タイプ | 600 / 900 / 1080 / 1320 | ポケモンから |
| 今のレベル | 1〜69 | 10 |
| 次のレベルまでのEXP | 0〜そのレベルの必要量 | そのレベルの必要量（貯まっていない） |
| 目標のレベル | 今のレベル＋1〜70 | 50 |
| 性格のEXP補正 | 上昇 / なし / 下降 | なし |
| 使えるアメ | 0〜9999 | 0 |
| ゆめのかけらの上限 | 数・なし | なし |
| 睡眠スコア | 0〜100（睡眠時間からも入れられる） | 100 |
| 睡眠EXPボーナスの数 | 0〜5 | 0 |
| おこうの使い方 | §3.6 の5通り | 使わない |
| リラックスチケット | 枚数（0〜） | 0 |
| 始める日 | 日付 | 今日 |

- 入力は端末に保存し、次に開いたときに戻す（チェッカーと同じ考え方）。

## 6. 出力

- ルートごとの **到達日数と到達日**、使うアメ・ゆめのかけら、あまるアメ。一番早いルートに印を付ける。
- 区切りのレベル（Lv.25・30・50・60 など、目標までにあるもの）に届く日。
- アメだけで届くときは「アメだけで届く（日数0）」と、使う数・ゆめのかけらを出す。
- C は週ごとの選択（島・睡眠）を一覧で出す。

## 7. データの出典と確かめ方

- 数値（累計EXP表、アメ1個のゆめのかけら、アメ1個のEXP、性格の倍率、睡眠EXPの式、おひるね島の式）は、にとよんツールから取った。にとよんツールにはライセンスの表示がないため、**コードは写さず、数値だけを使って計算は自分で書く**。出典はコードとREADMEに書く。
- wiki の表との照合（600タイプ、性格なし、Lv.10から）:

| 目標 | アメ | ゆめのかけら | wiki |
|---|---|---|---|
| Lv.25 | 178 | 12,623 | 一致 |
| Lv.30 | 273 | 22,688 | 一致 |
| Lv.50 | 993 | 166,155 | 一致 |
| Lv.60 | 1,853 | 537,974 | 一致 |
| Lv.70 | 3,080 | 1,679,761 | 一致 |

- レベルごとの必要EXP（Lv.25 = 600、Lv.50 = 1,066、Lv.70 = 3,255）と、Lv.10→41 の 19,458 も一致した。
- 900タイプの Lv.10→41 だけ、EXP が 29,187（wiki は 29,197）、ゆめのかけらが 117,852（wiki は 117,833）で、わずかに違う。他がすべて一致するので wiki 側の丸めか古い値と見て、にとよんツールの値を使う。
- 実装では、この表をテスト（`tests/`）にして、数値を写し間違えていないことを確かめる。にとよんツールの `calcExpAndCandy`・`calcDayToGetSleepExp`・`calcDayToNapExp` とも、条件をそろえて比べる（チェッカーの ver1.5 と同じやり方）。

## 8. 画面と置き場所（D5）

- 案1: `exp/`（新しいページ）。`checker/css/theme.css` の色・文字・部品と、表示テーマの切り替えをそのまま使う。チェッカーとは画面の下のリンクで行き来する。
- 案2: チェッカーの中のダイアログ。記録した個体から開けるが、チェッカーの画面と状態管理が大きくなる。
- 推奨は案1。チェッカーの記録から開く連携は、後の版で足す（§9）。

## 9. v1.0 で扱わないこと

- アメブースト（D3）、1日ごとに増えるアメ（D6）、ものひろいで拾うアメ・ゆめのかけら。
- ばんのうアメ・タイプのアメの組み合わせ（S/M/L）の提案。
- 進化に要るアメ、複数のポケモンの同時の育成計画。
- イベントの睡眠EXPボーナス（グッドスリープデー以外）。倍率を手で入れる欄を後で足すことはできる。
- チェッカーの記録からの読み込み。

## 10. 確かめていないこと

- グッドスリープデーの実際の日程が、満月の日（日本時間）の見込みとずれることがあるか（ずれたときは手で直す、D4）。
- 1日2回の睡眠計測のとき、睡眠EXPが計測ごとに入るのか、合計スコアで入るのか（v1.0 は1日の合計スコアで数える）。
- おひるね島のチケットが7日の途中で切れたときの、日ごとのEXPの切り替わり（v1.0 はチケットの日数ぶん600、そのあと150とする）。
- おひるね島で引き取ったとき、レベルが上がる順序（一度に上がる・あふれ分の扱い）は、上限でのあふれ以外は睡眠と同じとする。
