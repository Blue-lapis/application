## 2. 共通の天井カウンタ（`js/calc.js`）

- `segRolls(cap, n, ingP, berry, ing)`: 所持数0から n 回（小数）おてつだいする区間で、抽選が i 回で止まる確率 `P[i]`。前後の整数回の `nightRolls` を小数部分の割合で混ぜる。
- `runSegs(p, segs, ceil)`: 1日の区間の並び `segs`（`{ night, tap, n, rolls }`）で天井カウンタの分布を追う。
  - `tap` の区間（常にタップの日中）は、すべてのおてつだいで抽選し、ストックは発生しない。小数の分は、最後の1回をその割合で行うとみなして分布を混ぜる。
  - ほかの区間（3時間ごとの受け取りの区間と睡眠中）は、ストック2回まで・満タン後はキューの4回分までで、区間の終わりにストックを受け取る（ver1.0 の睡眠中と同じ）。
  - 毎日同じ区間なので、日の終わりの分布の変化が `CHAIN_TOL`（1e-12）未満になるまで日を進める（多くは2〜5日）。

## 3. スキルタイプの計算エンジン（`checker/js/skill/calc.js`）

計算条件 `env = { N, camp, mon, heal, tap, team, healAmt, healTimes }`。

1. **倍率** `mk`: 今までの項目に、性格のげんき回復量補正 `rec` とおてつだいボーナス `hb` を加える。
2. **スケジュール** `scheduleOf`: `curveOf` → `helpsPerTap` で区間ごとの小数のおてつだい回数を求める（食材タイプと同じ区切り）。
3. **所持数**: 最大所持数に `evo × 5` を含める。
4. **値**:
   - `metric(m, env)` = 自分の1日の期待発動回数。食材配列の個数の並びごとに `runSegs` を回し、出現確率で平均する。発動回数が小数なら `mixed` で平均する。
   - `teamGain(env)` = `TEAM_OTHERS(4) ×`（サブスキルなし・無補正で、スピード `HB_SPEED(5%)` ありの `metric` − `baseMetric`）。
   - `value = metric + (env.team && m.hb ? teamGain(env) : 0)`、`score = value / baseMetric`。
5. **キャッシュ**: 抽選回数の分布は中身ごとに番号を付けて共有し、`metric` は（条件・スキル確率・区間ごとの分布の番号）で、`runSegs` は（スキル確率・天井・区間ごとの分布の番号）で使い回す。
6. **表示用** `daily`: 日中 / 睡眠中の発動回数、おてつだい回数、睡眠中の抽選回数と満タンの確率、げんき。

## 4. 画面（スキルタイプの結果）

- 大きく出す値: 自分の発動回数（日中 / 睡眠中の内訳）。おてボ持ちで「含める」のときは、同じ枠に「おてボによるほかの4匹の増加 +○回」。
- 性能の欄に、げんき・発動回数の内訳（自分の発動回数・ほかの4匹の増加）を加え、最大所持数の内訳を「基礎＋進化×5＋サブスキル」にした。
- 計算条件の表示とげんきの行は、3タイプで同じ関数（`condText`・`genkiRow`）を使う。
- 先に計算しておく分布は、3タイプとも今の条件のまま対象レベルとチケットを変えたもの。

## 5. テスト

- `tests/check-dist.mjs` のスキルタイプを新しい条件にし、3時間ごと・発動回数が小数・性格のげんき回復の条件を加えた。
- きのみタイプ・食材タイプに影響がないことを、変更前後で71匹 × パラメーター4通り × サブスキル4通り × 性格4通り（4544件）の値が一致することで確かめた。
- 5枠の分布の計算は、常にタップ・発動回数3回で約18秒（ver1.2 は約15秒）、3時間ごとで約31〜34秒、発動回数が小数だとさらに約1.5倍。性格の分類が増えたこと、受け取りの区間が増えたこと、小数の発動回数を前後の整数回で2回計算することによる。Web Worker で計算し、一度計算した分布は保存する。
