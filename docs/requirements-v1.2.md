# ver1.2 要件定義：食材タイプの評価基準の見直し

[ver1.1](requirements-v1.1.md)（`main` の 9f9be70）を土台に、食材タイプの順位基準・げんきの考え方・パラメーター設定を見直す。今回は食材タイプだけを対象とし、きのみタイプ・スキルタイプの計算と画面は変えない。ver1.1 の「今後の予定」にある「食材タイプ・スキルタイプへのげんきモデル・受け取り設定の展開」のうち、食材タイプの分にあたる。

作りは [`design-v1.2.md`](design-v1.2.md) にまとめる。実装後に、作りを `design-v1.2.md` にまとめる（[`design-v1.1.md`](design-v1.1.md) と同じ形）。

## 1. 背景

ver1.1 のきのみタイプは、げんき・おてつだい回数・所持数・チームへの効果をにとよんツールに合わせて見直した。食材タイプは ver1.0 のままで、次の点が残っている。

- **げんきが悲観的すぎる（きのみタイプ ver1.0 と同じ問題）**: 起床時100から回復なしで10分ごとに1減るだけなので、睡眠開始から約70分で0（倍率1.0）になる。食材タイプは所持数が満タンになるまでの睡眠中のおてつだいで差がつくので、夜のおてつだいの速さが順位に直接効く。
- **おてつだい回数を整数で数えている**: 共通の `schedule` は日ごとの整数回を8日分平均する。きのみタイプは期待値（小数）で数えるように変えた。
- **最大所持数が捕まえた姿の値のまま**: きのみタイプは「進化1回ごとに+5」（にとよんツールと同じ）に変えたが、食材タイプは進化分を足していない。同じポケモンの図鑑値でもタイプによって所持数の扱いが違う。
- **性格のげんき回復量補正を計算していない**: きのみタイプは ver1.1 で入れた。
- **おてつだいボーナスのチームへの効果を数えていない**: 自分のおてつだい時間の短縮としてのみ計算している。
- **日中は常にタップする前提**: 所持数があふれないので、所持数アップ・食材確率アップの価値が睡眠中だけで決まる。

## 2. 評価の基準

### 2.1 順位の基準（全食材のエナジー ＋ おてボのチーム効果）

獲得した食材は1日で全部使い切る想定で、エナジーに換算して評価する。

```
順位の基準 = Σ（食材ごとの期待個数 × 食材1個のエナジー）  ← 狙い以外の食材も含む
          ＋（自分がおてつだいボーナスを持つとき）4 × ライチュウ1匹のきのみエナジーの増加分
```

- 食材1個のエナジーは食材ごとの基礎値（レシピボーナス・なべの容量・料理のレベルは考えない）。
- 無補正比の分母は、無補正個体（サブスキルなし・無補正性格。おてボなしなのでチーム分は0）のうち、上の値が最も大きい食材配列の値。
- 狙い食材は、画面に大きく出す個数を選ぶためだけに使う。順位・上位%には効かない（狙い食材を切り替えても分布は同じ）。
- 上位%の分布はサブスキル・性格25種・食材配列（捕獲時の出現率）を数え上げる（ver1.1 と同じ作り）。

### 2.2 おてボのチーム効果（ほかのメンバー）

- ほかの4匹は **ライチュウで固定**: Lv.50・いじっぱり（↑おてスピ ↓食材）・サブスキル きのみS / おてスピM（3枠目は空き）。
- 1匹あたりの増加分 = おてつだいスピード+5%（おてボ）ありのきのみエナジー − なしのきのみエナジー。
- きのみエナジーの計算はきのみタイプ ver1.1 と同じ規則。いいキャンプチケット・ヒーラー・回復量・発動回数は今の設定を反映する。
- **日中の受け取りは食材タイプの設定に合わせる**: 「3時間ごと」ならライチュウも3時間ごと、「常にタップ」ならライチュウも常にタップ（所持数があふれないので、食材おてつだい以外はすべてきのみ）。
- ライチュウの食材配列は、きのみタイプと同じく捕獲時の出現率で平均する。
- この計算はきのみタイプの画面・順位・分布には影響させない（6章）。

### 2.3 結果の表示

同じ枠の中に、個数を大きく、エナジーを小さめに出す。

| 行 | 大きく | 小さめ |
|---|---|---|
| 狙い食材 | 狙い食材の個数（日中 / 睡眠中の内訳） | エナジー（個数 × 1個のエナジー） |
| その他の食材 | 食材ごとの個数 | エナジー |
| チーム効果（おてボ持ちのときだけ） | ライチュウ4匹のきのみ +○○エナジー | ― |
| 合計 | ― | 順位の基準（エナジー） |

## 3. げんきのモデル

きのみタイプ ver1.1 のモデル（ヒーラー・料理による回復・性格のげんき回復量補正・小数のおてつだい回数）を、そのまま食材タイプにも使う。

- ヒーラー: なし / 1匹 / 常に81%以上。既定は **1匹**。回復量・1日の発動回数は詳細画面で変える（既定はきのみタイプと同じ）。
- ver1.0 の「げんき（10分ごとに減少 / 常に81%以上）」は、ヒーラーの選択肢に置き換える。保存済みの設定が「常に81%以上」ならそのまま引き継ぐ。
- 詳細ダイアログ（ver1.1 の 5.2）の食材タイプの項目「げんき（10分ごとに減少 / 常に81%以上）」は、きのみタイプと同じヒーラー・回復量・発動回数・初期値に戻すに置き換える。
- 詳細ダイアログの設定（ヒーラー・回復量・発動回数）は **きのみタイプと共通** にする（同じチームで使う想定）。どちらのタイプで変えても、もう一方にも効く。今後見直すスキルタイプも共通にする。

## 4. 所持数

- 最大所持数を、きのみタイプと同じく「捕まえた姿の値 + 進化1回ごとに5」にする。`js/ingredient/mons.js` に進化の回数 `evo` を加える。
- パンプジン（4つの大きさ）など、進化の回数はポケモンごとに確かめて README の表に載せる。

## 5. 日中の受け取り

- 設定: **常にタップ（ver1.0） / 3時間ごと**。既定は **常にタップ**。
- 食材タイプは満タンになると食材が増えないので、きのみタイプの「なし（いつのまに育成）」は選択肢にしない。
- **3時間ごと**: 起床から3・6・9・12・15時間後と就寝時に受け取り、区間ごとに所持数0から追う。区間内で満タンになった後は食材が増えない（睡眠中と同じ規則）。
- 所持数の少ないポケモン（ドクロッグ14・パンプジン(こだましゅ)10 など）は、3時間の区間でも満タンになりうる。

## 6. あわせて必要な対応

- 食材タイプの計算エンジン（`checker/js/ingredient/calc.js`）を、きのみタイプと同じ共通の `energyCurve`・`helpsPerTap` を使う形に書き換える。共通の `schedule` はスキルタイプだけが使う形になる。
- ライチュウのきのみエナジーは、食材タイプ側に新しいモジュールを作って計算する。きのみタイプの `checker/js/berry/calc.js`・`constants.js`・`mons.js` の既存の関数と値は変えない（読むだけ）。きのみタイプの結果が変わらないことを、変更前後の値の比較で確かめる。
- 食材1個のエナジー（19種）を共通データに加え、出典と取得日を README に書く。
- 計算条件 `env`（design-v1.1 の 2）の食材タイプの項目を `N`, `camp`, `mon`, `target`, `heal`, `healAmt`, `healTimes`, `tap`, `team` にする。
- 分布の保存キーに、ヒーラー・回復量・発動回数・受け取り・チーム効果の有無を加え、`MODEL_VERSION` を上げる（今は5）。
- 記録は表示のたびに今のパラメーターで計算し直す（ver1.0 と同じ）。
- `checker/README.md` の食材タイプの計算モデル・ポケモンの表（最大所持数）と、リポジトリ直下の `README.md` の共通の計算モデル（げんき）を更新する。
- 可能なら、にとよんツールの食材の値と同じ条件で比べ、差を README に書く（きのみタイプと同じ確かめ方）。

## 7. 今回は扱わないもの

- メインスキル（食材ゲットSなど）で得る食材。
- 料理のレシピボーナス・なべの容量・料理のレベル（組み合わせが大きく増え、ほかのメンバーやプレイヤーの設定にもよるため）。
- ほかのメンバーをライチュウ以外に変えること。
- スキルタイプへの展開（次の見直しで扱う）。
