# ver1.1 要件定義：きのみタイプの評価基準の見直し

ver1.0（`main` の 806bf31）を土台に、きのみタイプの順位基準・げんきの考え方・パラメーター設定を見直す。今回はきのみタイプだけを対象とし、食材タイプ・スキルタイプの計算と画面は変えない。

## 1. 背景

ver1.0 のきのみタイプは「自分のきのみの1日の期待エナジー」を無補正個体と比べて順位を出している。次の2点で、きのみタイプの役割を正しく評価できていない。

- **おてつだいボーナスの過小評価**: チーム全員のおてつだい時間を短くするのに、自分の短縮分しか数えていない。
- **げんきが悲観的すぎる**: 起床時100から回復なしで10分ごとに1減るだけなので、就寝時に約7、睡眠開始から約70分で0（倍率1.0）になり、夜の大半を最も遅い状態で計算している。実際はチームのヒーラーで日中にげんきが回復し、就寝時のげんきが夜のおてつだいの速さを決める。

## 2. 順位の基準

### 2.1 チーム貢献込みエナジー

順位の基準を次の値にする。

```
チーム貢献込みエナジー = 自分のきのみエナジー + 4 × (ほかのメンバー1匹のエナジー増加分)
```

- ほかのメンバーは「**同じポケモン・サブスキルなし・無補正性格・同じパラメーター**」の4匹とする（にとよんツールと同じ扱い）。
- ほかのメンバー1匹のエナジー増加分 = おてつだいボーナスあり（おてつだいスピード合計5%）のきのみエナジー − なしのきのみエナジー。
- 自分がおてつだいボーナスを持たないときは増加分0（サブスキルは重複しないので持つのは最大1つ）。
- 無補正比の分母は無補正個体の自分のきのみエナジー（無補正個体はおてつだいボーナスを持たないのでチーム分は0）。
- 結果には内訳（自分 / チームへの効果）を表示する。
- 「おてつだいボーナスのチームへの効果を含める」をオフにすると、ver1.0 と同じ「自分のきのみエナジーだけ」の基準になる（既定はオン）。

### 2.2 要確認

- おてつだいボーナスの5%が、ほかのメンバーのおてつだいスピード合計の上限35%に含まれるか。既定のほかのメンバーはサブスキルなしなので今回の計算には影響しないが、ほかのメンバーを選べるようにするときに必要。

## 3. げんきのモデル（きのみタイプ）

### 3.1 ヒーラー

- ヒーラーのスキルは **げんきオールS** のみを扱う（チーム全員を回復する）。
- ヒーラーの設定: **なし / 1匹 / 2匹 / 常に81%以上**。既定は **1匹**。
- ヒーラー1匹あたり、1日に **3回** 発動する（固定値）。1回の回復量は **18**（既定値）。
- ヒーラー n 匹で 1日 3n 回。起床から就寝までの起床時間を 3n + 1 等分した時刻に、1回ずつ回復する。
- スキルによる回復の上限は150。
- 「常に81%以上」は ver1.0 の「げんき常時81%以上」と同じ（げんきによる倍率が常に0.45）。

### 3.2 1日の流れ

- **起床時**: 睡眠による回復で上限（100。げんき回復ボーナスを持つときは105）まで戻る（睡眠スコア100の前提）。
- **起床中**: 10分ごとに1減る。3.1 の時刻にヒーラーの回復が入る。
- **睡眠中**: 回復せず、就寝時の値から10分ごとに1減る（0で止まる）。
- 睡眠は毎日8.5時間（ver1.0 と同じ）。

目安（起床中15.5時間でげんきは93減る）:

| ヒーラー | 就寝時のげんき | 睡眠中 |
|---|---|---|
| なし | 約7 | 約70分で0になり、残りは倍率1.0 |
| 1匹 | 約61 | 起床時に約10。大半は倍率0.52〜0.66 |
| 2匹 | 約115 | 起床時に約64。一晩中、倍率0.45〜0.52 |

### 3.3 今回は扱わないもの

- 起床時に、睡眠中にストックされたヒーラーのスキルがまとめて発動すること（朝のげんきが100を超える）。
- げんきエールS・げんきチャージSなど、げんきオールS以外のヒーラースキル。
- 睡眠スコアによる起床時の回復量の違い。

## 4. 日中の受け取り

- 設定: **なし（いつのまに育成） / 3時間ごと**。既定は **なし**（ver1.0 と同じ）。
- **なし**: ver1.0 と同じ。起床時に受け取り、次の起床まで所持数0から続けて追う。
- **3時間ごと**: 起床時に受け取り、以後、起床中は3時間ごと（起床から3・6・9・12・15時間後）に受け取って所持数を0に戻す。最後の受け取りから次の起床までは続けて追う。
- 受け取りの間の所持数の扱い（食材おてつだい、満タン後のいつのまに育成、キューに残った4回分）は ver1.0 の睡眠中と同じ規則を当てはめる。

## 5. パラメーター画面

にとよんツールにならい、2段構えにする。

### 5.1 メイン画面（性能の欄。画面を移らずにすぐ変えられる）

- 今の設定を1行にまとめて表示し、横に「詳細」ボタンを置く。
- すぐ変えられる設定:
  - ヒーラー: なし / 1匹 / 2匹 / 常に81%以上
  - 日中の受け取り: なし / 3時間ごと
  - いいキャンプチケット（ver1.0 のスイッチ）
  - おてつだいボーナスのチームへの効果を含める
- ver1.0 の「げんき常時81%以上」スイッチは、きのみタイプではヒーラーの選択肢に置き換える。保存済みの設定がオンなら「常に81%以上」として引き継ぐ。

### 5.2 詳細画面（下から出るダイアログ。サブスキル・性格の選択と同じ作り）

- げんきオールS の1回の回復量（既定18）
- ヒーラー1匹あたりの1日の発動回数（既定3）
- 余裕があれば、1日のげんきとおてつだいの倍率のグラフ（にとよんツールのげんきのグラフに相当）

## 6. あわせて必要な対応

- 上位%の分布はパラメーターごとに変わるので、分布の保存キー（`checker/js/distcache.js` の `cacheKey`）にヒーラー・受け取り・回復量・発動回数・チーム効果の有無を加え、`MODEL_VERSION` を上げる。
- 記録はサブスキル・性格を保存しているので、表示のたびに今のパラメーターで計算し直す（ver1.0 と同じ）。
- `checker/README.md` のきのみタイプの計算モデルと、リポジトリ直下の `README.md` の共通の計算モデル（げんき）に、きのみタイプだけの扱いとして追記する。

## 7. 今後の予定（ver1.1 では作らない）

- ヒーラーのポケモン（とスキルレベル・サブスキル・性格）を入力し、スキルタイプの計算エンジンでその期待発動回数を求めて反映する。
- 日中の受け取り間隔を自由に設定できるようにする。
- ほかのメンバーを別のポケモンに変えられるようにする。
- 食材タイプ・スキルタイプへのげんきモデル・受け取り設定の展開。
- 起床時のスキル発動、げんきオールS以外のヒーラースキル。
