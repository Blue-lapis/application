# ver1.1 要件定義：きのみタイプの評価基準の見直しと上位%の表示・確率モデルの整備

ver1.0（`main` の 806bf31）を土台に、きのみタイプの順位基準・げんきの考え方・パラメーター設定を見直し、あわせて3タイプ共通の上位%の表示と確率モデルを整備する。PR #30〜#38 で実装済み。計算式の詳細は [`README.md`](../README.md)（共通）と [`checker/README.md`](../checker/README.md)（タイプごと）、作りは [`design-v1.1.md`](design-v1.1.md) にある。

## 1. 背景

ver1.0 のきのみタイプは「自分のきのみの1日の期待エナジー」を無補正個体と比べて順位を出していた。次の点で、きのみタイプの役割を正しく評価できていなかった。

- **おてつだいボーナスの過小評価**: チーム全員のおてつだい時間を短くするのに、自分の短縮分しか数えていない。
- **げんきが悲観的すぎる**: 起床時100から回復なしで10分ごとに1減るだけなので、夜の大半を最も遅い状態で計算していた。実際はヒーラーと料理で日中にげんきが回復し、就寝時のげんきが夜のおてつだいの速さを決める。
- **参照ツールとの差**: 利用者が普段使う [にとよんツール](https://nitoyon.github.io/pokesleep-tool/iv/) とエナジーの期待値が一致しない。

また、上位%の表示で「順位」と「確率」が混同されやすく（例: 66位 / 2041通り を上位3.2%と読んでしまう）、食材配列の出現確率も等確率の仮定だった。

## 2. 評価の基準（きのみタイプ）

### 2.1 きのみエナジーだけで比べる

- 食材は料理によるばらつきが大きいので、評価はきのみのエナジーだけで行う（食材・メインスキルのエナジーは含めない）。
- おてつだい回数は期待値として小数で数える。
- にとよんツールのエナジーの「きのみ」と一致させる（検証結果は `checker/README.md`）。

### 2.2 チーム貢献込みエナジー

```
順位の基準 = 自分のきのみエナジー + 4 × (ほかのメンバー1匹のエナジー増加分)
```

- ほかのメンバーは「同じポケモン・サブスキルなし・無補正性格・同じパラメーター」の4匹（にとよんツールと同じ扱い）。
- 増加分 = おてつだいボーナスあり（スピード5%）のきのみエナジー − なしのきのみエナジー。自分がおてつだいボーナスを持たなければ0。
- 無補正比の分母は無補正個体の自分のきのみエナジー。
- 「おてボのチーム効果」を「含めない」にすると、自分のきのみエナジーだけで比べる（既定は「含める」）。

## 3. げんきのモデル（きのみタイプ）

### 3.1 ヒーラー

- ヒーラーのスキルは **げんきオールS** のみ（チーム全員を回復）。
- 設定: **なし / 1匹 / 常に81%以上**。既定は **1匹**。2匹は実際に使う人がいないので設けない（以前の保存値は1匹に戻す）。
- 1回の回復量（既定 **18**、整数）と1日の発動回数（既定 **3**、**小数第2位まで**）を詳細設定で変えられる。
- 起床中を「発動回数 + 1」等分した時刻（10分単位に切り捨て）に1回ずつ回復する。回復の上限は150。
- 発動回数が小数のときは、前後の整数回の日が小数部分の割合で混ざるものとして平均する。
- 「常に81%以上」はげんきによる倍率を常に0.45とする。

### 3.2 1日の流れ

- **起床時**: 睡眠による回復（100 × 性格のげんき回復量補正、上限100。げんき回復ボーナス持ちは105）。回復量が上限に届かないときは、前の晩の残り＋回復量。
- **起床中**: 10分ごとに1減る。ヒーラーと料理（8時起床で10時・14時・20時。そのときのげんきに応じて1〜9）で回復する。
- **睡眠中**: 回復せず、就寝時の値から10分ごとに1減る（0で止まる）。げんき1以下は倍率1.0。
- 性格のげんき回復量補正（↑1.2倍 / ↓0.88倍）は睡眠とげんきオールSに掛ける（料理には掛けない）。性格の分類に「げんき回復」を加える。
- 進化するポケモンは、進化1回ごとに最大所持数+5。

### 3.3 扱わないもの

- 起床時に、睡眠中にストックされたヒーラーのスキルがまとめて発動すること。
- げんきオールS以外のヒーラースキル、睡眠スコアによる回復量の違い。

## 4. 日中の受け取り（きのみタイプ）

- 設定: **なし（いつ育） / 3時間ごと**。既定は **なし**。
- **なし**: 一度も受け取らないので、すべてのおてつだいがきのみになる（いつのまに育成）。
- **3時間ごと**: 起床から3・6・9・12・15時間後と就寝時に受け取り、区間ごとに所持数0から追う。

## 5. パラメーター画面

にとよんツールにならい、2段構えにする。切り替えはヒーラーなどと同じ2〜3択のボタン（スイッチは使わない）。

### 5.1 メイン画面（性能の欄）

- きのみタイプ: **日中の受け取り**・**いいキャンプチケット**。
- 食材タイプ・スキルタイプ: **いいキャンプチケット**。
- 今の設定を1行にまとめ、横に「詳細」ボタンを置く。

### 5.2 詳細ダイアログ

- きのみタイプ: ヒーラー（なし / 1匹 / 常に81%以上）、おてボのチーム効果（含めない / 含める）、げんきオールSの回復量・発動回数、初期値に戻す。
- 食材タイプ・スキルタイプ: げんき（10分ごとに減少 / 常に81%以上）。

### 5.3 結果の表示（きのみタイプ）

- 大きく出す値は順位の基準（チーム効果込み）。日中・睡眠中は **自分のきのみエナジー** の内訳とし、チーム効果は別の行（「おてボによるほかの4匹の増加」）に出す。
- 条件の欄に就寝時・起床時のげんきと、性格のげんき回復量補正を出す。

## 6. ダイアログの操作（3タイプ共通）

- サブスキル・性格・パラメーターのダイアログは1画面に収め、閉じるボタンまでスクロールしなくてよいようにする（下端の操作欄は固定）。
- サブスキルのダイアログは、すべての枠が埋まったら自動で閉じる。直したいときは開き直す。

## 7. 上位%の表示と確率モデル（3タイプ共通）

### 7.1 順位と確率を分ける

- 画面下のバーは **無補正比・同等以上の確率・平均何匹に1匹** だけを出す。
- 「性能値の順位」（分布の中で自分より高い値の数 + 1 / 行数）は参考値として結果の行に出し、確率とは一致しないことを注記する。
- 記録の一覧には確率と何匹に1匹だけを出す。
- 抽選条件を注記する: フレンドメダルによる金枠確定なし、食材配列は捕獲時の出現率。フレンドメダルの設定は設けない。

### 7.2 食材配列の出現確率

- [RaenonX の調査](https://hackmd.io/@raenonx-pokemon-sleep/rJj6yeIlWe) に合わせ、候補が2つのスロット（Lv.30 など）は A 1/3・B 2/3、3つのスロット（Lv.60）は等確率、スロットどうしは独立とする。
- 食材タイプの分布と、きのみタイプ・スキルタイプで配列ごとの値を平均するときの重みの両方に使う。

### 7.3 整合性

- 分布の確率の合計が1。
- 平均何匹に1匹 = 丸める前の同等以上の確率の逆数。
- 無補正比の差が相対 1e-7 以内のものは同じ性能として1行にまとめ、順位・確率も同じ基準で比べる。
- 以上を `node tests/check-dist.mjs` で確かめられるようにする。
- 計算方法・公開版・データ・条件が変わったら、保存済みの分布を使わずに計算し直す。

## 8. 今後の予定（ver1.1 では作らない）

- ヒーラーのポケモン（スキルレベル・サブスキル・性格）を入力し、期待発動回数を求めて反映する。
- 日中の受け取り間隔を自由に設定できるようにする。
- ほかのメンバーを別のポケモンに変えられるようにする。
- きのみタイプで食材配列を入力できるようにする。
- 食材タイプ・スキルタイプへのげんきモデル・受け取り設定の展開。
